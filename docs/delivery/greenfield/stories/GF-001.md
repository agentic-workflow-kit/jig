# GF-001 — Private Node/TypeScript workspace substrate

## Outcome, value, and why now

Create the private Node/TypeScript/pnpm/Turbo substrate that can express the approved runtime seams as a hermetic dependency graph. It releases repeatable local and CI validation, affected-task caching, and failure isolation before any Jig behavior is made reachable. This is the earliest safe point because later stories need one reviewed graph in which semantic packages and test evidence can be isolated. It does **not** release a runtime, CLI, port, provider, storage implementation, or lifecycle authority.

## Governing paths and stable IDs

- [`runtime.md`](../../../redesign/design/runtime.md) fixes the six-unit deployment shape and requires authority to remain in the controller rather than in tooling or stores.
- [D10](../../../redesign/design/decisions/D10-runtime-decomposition.md) owns the private modular package decomposition decision; `DR-2` records its implementation-realization choice.
- [`architecture-conformance.md`](../../../redesign/design/architecture-conformance.md) makes versioned conformance evidence a gate, not a test-report convention; `DR-8` owns the private deterministic testkit/harness realization.

This story carries only `DR-2` and `DR-8`. It deliberately carries no `RT-*`, `PORT-*`, `ID-*`, `SCH-*`, `EV-*`, `OPC-*`, `FC-*`, or `BND-*` semantic contract: adding one would falsely create runtime behavior in a tooling story.

## In-scope and non-goals

In scope: private workspace roots, Node/TypeScript/pnpm/Turbo configuration, project references, explicit task inputs/outputs, immutable CI action references, dependency-boundary rules, and hermetic fixtures for cache and failure-isolation proof.

Out: product schemas; controller code; any runtime unit; ports/transports; credentials; source, ledger, artifact, session, workspace, verification, or delivery adapters; package names/counts that would pre-empt a later approved seam realization; public publishing; registry configuration; and cleanup of a prior generation. A package exists only when a later story has a bounded owner and acceptance oracle.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The unit is a private build/test workspace, not `SYS-JIG`. It exposes no product port and cannot import, instantiate, or configure an adapter. Inputs are checked-in non-secret configuration and fixture sources; outputs are local/CI task artifacts and cache metadata, neither authoritative nor durable Jig facts. The CI/workspace identity may label a build, but it is not an `ID-*` and cannot mint an event, transition, Operation, or provider capability.

The only authority is build orchestration: it may schedule declared tasks, never decide a Jig lifecycle. The fence is structural: dependency rules reject a task/package edge that crosses an undeclared future seam; no task may inject credentials, expose a runtime entrypoint, or dispatch an external effect. `RT-CONTROLLER`, stores, and `RT-OPERATOR` are absent, so none can gain power here.

## Observable success and terminal outcomes

Success is a clean checkout where declared private tasks are reproducible, an affected-change fixture runs only its declared dependents, and an intentionally failing lane cannot make an unrelated lane appear successful. The durable evidence is a versioned CI/local report bound to the exact source/content digests and toolchain lock state; it releases GF-002's codec implementation dependency.

Terminal outcomes are `Passed` or `Failed` build evidence, not Run/Story outcomes. `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, acceptance, landing, and dispatch are impossible because this story creates no Run, controller, or effect path.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Malformed configuration, lockfile drift, forbidden imports, missing declared outputs, nondeterministic task inputs, or a failed fixture fail the task closed. These are build failures, not a product `FC-*`; no product failure record is representable. CI retry may re-execute the whole hermetic task from immutable inputs, but it cannot reuse an uncertain external effect because none exists. Cache loss is recoverable by recomputation; cache hits are advisory and never proof of a pass. Cleanup may remove only disposable build outputs under the workspace policy; it must not erase checked-in evidence. Resume reruns from source and lockfile, with no persisted Jig state to reconstruct.

## Security and trust: validation, credentials, redaction, and authority widening

Validate configuration schema, lockfile integrity, package-edge allowlists, task input/output declarations, and immutable CI action references. Install/build scripts run with least privilege; credentials are neither required nor accepted by test fixtures. Logs redact environment values and never persist secrets. A cache, CI provider, plugin, or future adapter is untrusted evidence until its declared task verifies it. No configuration switch may turn an unqualified adapter into a task dependency or runtime command; such paths remain absent/unreachable.

## Deliverables without delegated algorithm invention

- Private workspace and TypeScript reference configuration under the repository's approved tooling paths, with no public package metadata.
- A declared Turbo task graph with explicit inputs, outputs, cache policy, and independent-lane fixture.
- Static dependency guard and fixtures proving an allowed edge, a forbidden edge, affected-cache behavior, and failure isolation.
- Versioned test/evidence metadata consumed later by GF-004.

`DR-2`: Engineering selects private pnpm packages organized by approved dependency/runtime seam, constrained by D10's authority allocation; evidence is the graph and static guard; fallback is the smallest graph that preserves the same seams. `DR-8`: Engineering selects a deterministic private testkit/harness compatible with the toolchain, constrained by exact-candidate evidence; evidence is reproducible fixture output; fallback is no conformance claim. Neither choice authorizes a controller algorithm, protocol, policy, or provider.

## Test and evidence obligations

Run deterministic workspace install/compile/config tests; static forbidden-edge tests; cold/warm affected-cache fixtures; and a deliberately failing independent-lane fixture. Contract, replay, crash, timeout, recovery, provider, and E2E product tests are N/A: no product contract, durable fact, clock, adapter, or effect is reachable; the structural absence is proven by the graph guard and inspection. Record toolchain/lockfile digests, task definitions, exact candidate digest, fixture inputs, and outputs. `CF-*` suites are not yet claimed; GF-004 supplies their recorder.

## Exact acceptance

An independent reviewer verifies the exact candidate content digest, baseline relation, lockfile/toolchain metadata, graph report, static-guard report, cache and failure-isolation evidence, and that no runtime or adapter entrypoint was added. Required findings are resolved or explicitly rejected by the authorized owner; stale, self-authored, partial, or differently bound evidence fails. The reviewer accepts this substrate only; authoritative landing remains the separate reviewed PR merge/CI proof.

## DR choices

Their owner is Engineering, subject to D10 and the conformance contract; alternatives such as a monolith, public package publishing, or a hosted test service are deferred. If a choice needs a new authority seam, provider capability, or public contract, stop with `OWNER_DECISION_REQUIRED` rather than widening the story.

## PR boundary, relative size, and split

# GF-055 — Thin CLI and terminal/file channels

## Outcome, value, and why now

Provide an operator-initiated command line over GF-054's private SDK, with redacted human and
machine results and the approved terminal/file notice route. It enables the documented local
workflow without creating an independent control plane. It follows intake, durable notice, and
SDK parity; it does not add scheduler, webhook, service endpoint, or CLI-specific authority.

## Governing paths and stable IDs

`docs/product/jig.md` owns the operator workflow; `runtime.md` owns private `PORT-CONSUMER`.
`DR-7` selects a thin CLI over the SDK and `DR-12` selects terminal/append-only-file channels.
All lifecycle/event/operation identities remain owned by delegated ports; CLI only carries their
versioned schemas and correlation IDs.

## Dependencies plus start evidence

Require merged GF-020 source/intake contract, GF-052 notice channel evidence, and GF-054 exact SDK
contract/`CF-CONSUMER` evidence. Confirm selected baseline, current CLI/SDK schema digest, caller
principal configuration, terminal/file permissions, and that no real provider is being assumed from
local command availability.

## In-scope and non-goals

In scope: parse bounded commands, invoke SDK, render redacted JSON/human output, and tail approved
terminal/file notice projection. Exclude direct port/controller/store calls, daemon/scheduler/webhook,
shell evaluation, arbitrary file ingestion, public distribution, policy changes, and a new notice
or decision transport.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

CLI is a thin `RT-OPERATOR` consumer at `PORT-CONSUMER`. It validates command/version/file reference,
binds configured principal, calls SDK, and emits SDK result with source/candidate/Run/notice/export
identities unchanged. Durable truth remains ledger/artifact records; local history/output files are
non-authoritative. CLI cannot decide/approve/dispatch/finalize/publish beyond SDK's validated
principal and port guards; terminal/file rendering cannot alter notice urgency/content or lifecycle.

## Observable success and terminal outcomes

For preview→approve→start→inspect/watch/why→decide→stop/export, CLI outcome exactly matches SDK
including `Landed`, `Blocked`, `Parked`, `Rejected`, `NotRun`, and `Stopped`; no empty exit code or
pretty output masks a failure. Machine results are schema/version/head bound; human results redact
secrets and direct users to the exact durable condition. Invalid command/input emits no event.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Invalid parsing/version/path is `FC-VALIDATION`; caller mismatch `FC-AUTHORITY`; unavailable SDK/
terminal file `FC-MECHANISM`; delegated bound/fence/status pass through unchanged. CLI records no
effect intent and never retries uncertain SDK effects; it renders stable effect/reconciliation state.
Interrupted output can be rerun as a new read; command recovery rereads durable result by identity.
Cleanup removes only transient rendering files, preserves append-only notices/receipts, and cannot
resume or modify work outside an authorized SDK call.

## Security and trust: validation, credentials, redaction, and authority widening

Use strict argument grammar, canonical paths rooted in configured safe locations, bounded stdin,
no shell interpolation, and caller binding. Credentials stay in SDK/runtime memory; command lines,
terminal output, machine JSON, file channel and diagnostics redact them. Missing/ambiguous config
fails closed. CLI cannot configure an unqualified adapter or turn provider/channel response into
authority.

## Deliverables without delegated algorithm invention

Deliver command schema/help, private entrypoint, SDK invocation map, redacted human/JSON renderer,
safe file/terminal writer, fixtures, and parity evidence. `DR-7`: private thin SDK consumer;
`DR-12`: terminal/file route. Arye owns both; constraints no direct internals/no new channel
authority, evidence parity corpus, fallback unavailable command/channel, and new command semantics
require `OWNER_DECISION_REQUIRED`.

## Test and evidence obligations

Test parser/path/oversize/unknown flag negatives, caller/cross-scope negatives, secret-redaction,
machine schema, output interruption, terminal/file permission failure, delegated replay/fence/bound
outcomes, notice tail dedup, and full local workflow parity with SDK. Update `CF-CONSUMER` and CLI
E2E parity evidence with exact build/schema/fixture/result digests. Provider tests remain delegated
to provider stories; CLI cannot certify them.

## Exact acceptance

Independent review verifies exact CLI/SDK candidate digests, command-to-SDK matrix, redacted outputs,
negative parser/authority corpus, and parity evidence. Any direct access, secret leak, masked terminal
failure, or divergent result fails; acceptance does not constitute landing.

## DR choices

`DR-7` and `DR-12` retain private CLI and terminal/file choices, owner Arye, constraints/evidence/
fallback above, and no deferred alternative may be enabled without owner decision.

## PR boundary, relative size, and split

M, one SDK-consumer parity oracle. Expected CLI/rendering/tests only; excludes MCP/provider work.
No split unless terminal/file mechanism requires independent real qualification; then it is a
separate unconfigurable realization half.

## Definition of Ready

- GF-020/052/054 exact evidence, CLI schema, principal, file boundary, and DR choices are current.
- The complete delegated workflow/result matrix and redaction oracle are reviewable.

## Definition of Done

- CLI is thin, safe, redacted, and SDK-equivalent; no local state or output alters durable truth.
- Required parser, hostile input, fault, replay, redaction, terminal/file, and E2E parity proof passes.
- Exact review, `git diff --check`, repository checks, CI, and landing proof pass.

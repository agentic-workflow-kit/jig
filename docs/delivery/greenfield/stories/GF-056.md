# GF-056 — Thin private stdio MCP adapter

## Outcome, value, and why now

Expose the same private SDK workflow through a local stdio MCP adapter for a configured first-party
consumer. It lets a tool client use validated requests without a second semantic protocol. It follows
the SDK facade and completes operator parity; it is not a public/multitenant network service,
provider, or authority source.

## Governing paths and stable IDs

`concepts.md` permits the private MCP adapter and `runtime.md` reserves `PORT-CONSUMER` as the
private facade. `DR-7` selects thin private SDK/CLI/stdio realization. MCP method names/transport
correlation are not lifecycle identities; existing SDK schema/Run/Story/notice/export identities
remain authoritative.

## Dependencies plus start evidence

Require merged GF-054 exact SDK API digest, principal binding, `CF-CONSUMER` results, and independent
review. Freeze supported protocol/schema versions, stdio framing limits, configured local principal,
and private host boundary. Missing or mismatched protocol/posture leaves adapter unavailable.

## In-scope and non-goals

In scope: strict stdio framing, schema mapping, principal binding, SDK delegation, and redacted
result mapping. Exclude network listener, public registry/discovery, multi-tenancy, direct internals,
MCP-originated events, credential forwarding, provider qualification, and tool-defined workflow logic.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The adapter is an `RT-OPERATOR` private consumer that calls GF-054 over `PORT-CONSUMER`. It validates
protocol version, canonical tool input, configured local principal, request size, and correlation;
it returns SDK's typed result/status and exact identity bindings. Stdio transcript is not truth;
ledger/artifact records remain so. The transport cannot approve, decide, dispatch, finalize, or mint
events/grants; it can only request the same SDK operation already authorized for its bound principal.

## Observable success and terminal outcomes

SDK, CLI, and MCP produce equivalent accepted/refused result schemas, redaction, authority outcome,
and terminal semantics for a fixed request. `Stopped` remains non-resumable and all `Blocked`,
`Parked`, `Rejected`, and `NotRun` outcomes are explicit. Invalid frame/version/principal produces no
durable mutation and a typed refusal.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Malformed/oversized/unknown frame is `FC-VALIDATION`, identity mismatch is `FC-AUTHORITY`, broken
stdio/SDK is `FC-MECHANISM`; owning-port `FC-*`/`BND-*` pass through. Adapter creates no effect
identity and never retries an uncertain SDK operation. On reconnect use a new validated request and
reread durable result by returned identity; discard partial transcript. Cleanup closes streams only,
preserves SDK/ledger facts, and cannot resume work.

## Security and trust: validation, credentials, redaction, and authority widening

Bound frame count/size/depth and reject duplicate/ambiguous fields; authenticate the configured local
caller through the host binding. Credentials remain runtime-memory references and are never MCP
arguments, transcript, tool descriptions, errors, or logs. Redact all result diagnostics per SDK.
Unknown host proof fails closed; no tool/client/provider assertion can widen scope or expose an
unqualified adapter.

## Deliverables without delegated algorithm invention

Deliver private stdio adapter, versioned method/schema map, strict framing validator, SDK result
bridge, redaction harness, protocol fixtures, and parity evidence. `DR-7`: owner Arye; selected
private stdio facade; constraints no network/public promise/no direct internals/no authority;
evidence three-surface parity; fallback adapter absent; any service/method semantic requires
`OWNER_DECISION_REQUIRED`.

## Test and evidence obligations

Run protocol/schema/version/oversize/fuzz tests, malformed/duplicate frame tests, local/cross-
principal negatives, transcript secret scans, stream interruption/reconnect, SDK error/bound/fence
passthrough, no-durable-event assertions, and SDK/CLI/MCP parity matrix including terminal states.
Update `CF-CONSUMER` with exact protocol/build/host-posture/fixture/result digests. No real provider
or network E2E applies because transport remains private local stdio.

## Exact acceptance

Independent review binds candidate/target and protocol/SDK digests, host posture, negative corpus,
redaction scans, and parity output. Network exposure, client-minted authority, direct runtime access,
or unbound terminal result fails. Acceptance is not merge/landing proof.

## DR choices

`DR-7` records the question/private stdio adapter, owner Arye, selected bounded option, constraints,
parity evidence, unavailable fallback, and consumer-only blast radius. There is no other DR.

## PR boundary, relative size, and split

S/M, one transport-to-SDK parity oracle. Expected adapter/protocol/tests only; excludes CLI and
network service. No split unless protocol qualification becomes independently failing, in which case
semantic core stays unconfigurable.

## Definition of Ready

- GF-054 exact candidate, local host/principal, protocol versions/limits, and DR-7 evidence are current.
- Method map, redaction, terminal parity, and no-authority constraints are explicit.

## Definition of Done

- Adapter is private, thin, fail-closed, redacted, and cannot mint authority or durable events.
- Required hostile-input, identity, fault, recovery, secret, and three-surface parity proof passes.
- Exact review, `git diff --check`, repository checks, CI, and separate landing proof pass.

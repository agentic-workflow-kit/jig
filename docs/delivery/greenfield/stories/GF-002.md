# GF-002 — Canonical identity and boundary codec

## Outcome, value, and why now

Deliver one strict, versioned JSON framing and validation library for all twenty-two canonical identity representations, with canonical bytes and digest vectors. It makes later ports, records, evidence, and fences compare one exact subject instead of accepting equivalent-looking encodings. It is earliest after GF-001 because it needs the private graph, and it enables GF-003's typed port contracts. It does not authorize lifecycle minting, ledger commits, Operations, or any provider effect.

## Governing paths and stable IDs

[`data-and-identity.md`](../../../redesign/design/data-and-identity.md) controls the representation, scope, collision, digest-staging, and fail-closed rules. This story implements every identity representation: `ID-RUN`, `ID-STORY`, `ID-TXN`, `ID-EVENT`, `ID-OP`, `ID-CAND`, `ID-GEN`, `ID-PRINCIPAL`, `ID-SESSION`, `ID-FINDING`, `ID-GRANT`, `ID-SOURCE-REQ`, `ID-REGISTRY`, `ID-TARGET`, `ID-AUTH`, `ID-EVSUBJ`, `ID-PARK`, `ID-OBLIGATION`, `ID-SETTLEMENT`, `ID-MANIFEST`, `ID-NOTICE`, and `ID-EXPORT`. It also carries `DR-1`: strict versioned JSON and deterministic canonical bytes. The identity library validates representation and binding only; the named owning stories later mint each identity.

## Dependencies plus start evidence

GF-001 must be merged and independently accepted on the selected baseline, with its graph guard and toolchain evidence current. Start from that merged commit plus the locked data-and-identity schema vocabulary. The start package must demonstrate that no other codec/serializer is accepted at a boundary. No provider is qualified or configurable; a fake cross-runtime consumer may use vectors only.

## In-scope and non-goals

In scope: JSON frame version tag, canonical field ordering/encoding rules, parse/format/validate functions, exact size/depth/string/number limits, identity grammar and scope checks, staged digest helpers, typed errors, and golden vectors.

Out: `SCH-*` business-schema payloads, owner/principal authentication, lifecycle rules, identity allocation/ledger writes, storage layout, alternate encodings, permissive legacy parsing, transport serialization, and a universal serialization framework. Strict JSON does not imply a selected algorithm beyond the governing canonicalization contract.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

This is a pure shared boundary library used later by the six runtime units. It has no named port and no durable writer. Inputs are untrusted bytes plus declared frame/schema version; outputs are either canonical bytes/typed values or a typed rejection. It represents all 22 identities but only their named owners may mint them: for example `CP-INTAKE` mints `ID-RUN`, `CP-TRANSITION` commits `ID-EVENT`/`ID-TXN`/`ID-OP`, the registry allocates `ID-AUTH`, and their later stories enforce those facts. The codec cannot assert that an identity is committed, current, authorized, or witnessed.

The fence is API and dependency direction: construction paths require the owning record/fact witness supplied by the caller's later semantic layer; raw strings or provider claims never acquire authority merely because they parse. No persisted facts exist in this story; vector fixtures are non-authoritative test inputs.

## Observable success and terminal outcomes

Success means independent consumers obtain identical canonical bytes/digests for every valid vector, and every identity parses only in its exact hierarchical scope. A malformed, unknown-version, duplicate-key, noncanonical, ambiguous, oversized, cross-scope, or digest-staging-invalid frame returns the specified typed boundary error and no value. It releases GF-003 and later semantic models.

Terminal outcomes are `valid canonical value` and `typed rejection`; no Run/Story state, `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, effect, or acceptance outcome can result. A rejected frame cannot be coerced or normalized silently.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Boundary failures are typed `FC-INPUT` for malformed/unknown/oversized/noncanonical framing and `FC-SUBJECT` for invalid identity scope, binding, or staged-digest relation. The caller must preserve the raw input only in a redacted/quarantined diagnostic form and fail closed. Parsing has no effect, so a caller may retry the same immutable bytes; it may not substitute a normalization or a newly generated identity. There is no timeout, external effect, reconciliation, recovery, or cleanup state. A process restart recreates results from the same bytes; no codec cache is authoritative.

## Security and trust: validation, credentials, redaction, and authority widening

Apply byte, nesting, collection, string, numeric, duplicate-key, Unicode/normalization, and schema-version limits before allocation-heavy work. Bind identity paths exactly and reject free-form `ID-EVSUBJ` subjects. The codec requires no credential; logs/vectors contain synthetic identifiers only, and rejected payloads are length-limited/redacted. A provider's supplied JSON, manifest, evidence, or fallback cannot widen authority: parsing produces at most an untrusted typed value. No adapter can be selected by frame version; unqualified adapters remain unreachable because this library has no dispatch API.

## Deliverables without delegated algorithm invention

- Private versioned JSON frame and canonical-byte package, including explicit limits and typed `FC-INPUT`/`FC-SUBJECT` result family.
- Complete 22-identity grammar/constructor/validator surface with staged-digest hooks but no semantic allocation.
- Immutable golden vectors for valid, invalid, ambiguous, oversized, duplicate, cross-scope, and digest-bound cases, usable by independent runtimes.
- Property/fuzz corpus and evidence format for vector version, implementation digest, inputs, and oracle outputs.

`DR-1` is Engineering's strict JSON-only selection: canonical bytes and runtime validation are constrained by `data-and-identity.md`; evidence is cross-runtime vectors and hostile-input proof; fallback is rejection, never a permissive codec. No delegated lifecycle or cryptographic protocol is chosen here.

## Test and evidence obligations

Required: deterministic unit/schema and cross-runtime golden-vector tests; property/fuzz tests for grammar and canonicalization; hostile-input limits; negative-authority tests proving parse does not mint/dispatch; and replay tests proving byte-stable output. Crash, timeout, reconciliation, provider, and E2E tests are N/A because this library has no durable state, clock, adapter, or effect; the test graph must prove that absence. Record vector corpus/version/digest, implementation digest, frame version, test seed, and exact candidate digest. `CF-BINDING` operands may begin here, but no `CF-*` pass is published before GF-004 records it.

## Exact acceptance

An independent reviewer checks the complete identity list against the governing table, frame/version and canonical vector metadata, rejection coverage, size bounds, and proof that raw values cannot imply commitment/authority. Acceptance requires exact candidate content digest and all test inputs/results; a self-authored or stale vector report is insufficient. PR landing is separately proven by required CI and merge state.

## DR choices

`DR-1` applies: question—how are boundary bytes represented? Owner—Engineering. Selected bounded option—strict versioned JSON with deterministic canonical bytes. Immutable constraints—no ambiguous or alternative encoding, all 22 forms and staged bindings remain exact. Deferred alternatives—other encodings/legacy parsing. Failure fallback—typed reject/quarantine. Any need to make parsing establish lifecycle truth is `OWNER_DECISION_REQUIRED`.

## PR boundary, relative size, and split

**M.** One oracle: the same exact bytes and identities accept/reject identically. Expected paths are the codec, vectors, and test fixtures. Do not combine it with a port, ledger, or identity allocator. A split into `GF-002a` frame/core and `GF-002b` independent language binding is allowed only if both consume the identical immutable vectors; the first exposes no adapter or semantic minting.

## Definition of Ready

- GF-001 is merged with current graph evidence.
- The 22 `ID-*` rows, frame limits, digest staging, `DR-1` owner/constraints, and error taxonomy are enumerated.
- Strict non-goals and no-authority fence are testable.

## Definition of Done

- Every frame boundary validates its immutable version and rejects unknown/ambiguous input.
- All 22 identity representations and canonical vectors pass deterministic and adversarial proof.
- `FC-INPUT`/`FC-SUBJECT` are typed, and no parsed provider fact can mint authority.
- Exact evidence, `git diff --check`, required checks/CI, and independent exact-candidate review pass.

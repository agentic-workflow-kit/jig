# GF-047 — Qualified local verification provider

## Outcome, value, and why now

Qualify the separate local-command verifier and remote-gate observer against GF-042 exact effect-free semantic contract, making only that exact manifest/build/environment configurable. It cannot accept, choose policy, run effect-needing checks, or substitute for delivery; no qualification evidence transfers across provider build, manifest, environment, posture, or suite version.

## Governing paths and stable IDs

Mechanism/provider contracts owns capability manifest, qualification and CF-GATE-PROVIDER; review execution owns exact subject/effect-free verification and remote observations. PORT-VERIFY, EV-CHECK-OBSERVATION, CF-MECH-VERIFY, CF-GATE-PROVIDER, and DR-5 map the sole provider boundary.

## Dependencies plus start evidence

Require merged GF-022 provider approval/proof machinery and GF-042 semantic contract/CER. Freeze owner-approved manifest, provider build, command allowlist and native posture, environment fingerprint, credential names, clean checkout/scratch/no-egress contract, suite/adversarial versions, and exact candidate vectors. Any drift makes provider unavailable.

## In-scope and non-goals

Scope is local command execution and remote-gate observation realization only. Exclude semantic policy/check selection, acceptance, workspace/write/network effects, final delivery, real forge, and any alternate verifier/host. Unsupported effect-needing check is rejected, not routed silently.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

Local verifier is PORT-VERIFY mechanism behind admitted capability binding; controller still authorizes each ID-OP from frozen class/basis/fence; ledger persists intent and EV-CHECK-OBSERVATION. Provider receives read-only exact checkout, discarded scratch, permitted command/environment, no egress; it returns attestation only. It cannot mint authority, mutate subject, select class, or access delivery credentials.

## Observable success and terminal outcomes

Success is current exact CF-MECH-VERIFY pass plus CF-GATE-PROVIDER admission for this provider tuple; only then configuration may expose it. Observation pass/fail retains GF-042 semantics. Drift/fail/expiry leaves provider unconfigurable, affected work NotRun/parked; it cannot accept/Land/release or make effects legal.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Command timeout/result loss is bounded by BND-WAIT-MECHANISM; because execution is enforced effect-free, replacement uses new authorized ID-OP. Effect assertion, subject/fence/env mismatch, stale manifest, or malformed output is FC-SUBJECT/AUTHORITY/MECHANISM/EVIDENCE and fails closed. Recovery validates durable intent/receipt/result; no blind retry of uncertain external effect is possible because none is allowed; scratch is discarded safely.

## Security and trust: validation, credentials, redaction, and authority widening

Validate executable digest/allowlist, args/class, environment, checkout/basis/fence, capability proof age, provider identity, no egress/write and result limits. Credential names resolve only in provider memory and no forge credential is permitted. Redact/quarantine output; hostile command/output cannot widen manifest/authority. Remote gate is observation-only and its fact is freshness/integrity checked.

## Deliverables without delegated algorithm invention

Deliver local verifier adapter, manifest binding/admission, command/environment sandbox enforcement, remote observer, qualification runner/CER, drift invalidation, and configuration reachability guard. DR-5 Configuration selects local verifier only within approved profile; exact CF evidence is mandatory and fallback unavailable. No algorithm beyond GF-042 contract is delegated.

## Test and evidence obligations

Contract tests exact command/class/basis/fence and no effect; adversarial tests write/network/escape, undeclared env/credential, wrong digest, stale proof, hostile output; replay/crash/timeout/replacement; provider qualification test exact build/manifest/environment/posture; E2E deterministic pass/fail and remote observation. Run complete CF-MECH-VERIFY and CF-GATE-PROVIDER with versioned CER.

## Exact acceptance

Independent reviewer freezes provider build, manifest/owner approval, environment/posture, command and authority limits, suite/adversarial/CER, drift and configuration guards, and exact GF-042 vectors. PASS admits only that tuple; it is not acceptance, landing, or proof for a changed provider.

## DR choices

DR-5 Configuration: owner-approved local verifier profile, exact manifest/build/environment and CF gate; alternatives need own provider story; fallback unavailable. DR-4 remains fixed by GF-042 and has no new choice.

## PR boundary, relative size, and split

M; provider realization only, deliberately split from GF-042 semantics. Expected adapter/manifest gate/qualification fixture/tests/config guard. Exclude policy, workspace, delivery, and other providers; no further split because one provider gate is the oracle.

## Definition of Ready

- Named predecessors are merged/current on selected baseline; exact subject evidence is frozen.
- IDs, port, principal/fence, durable facts, FC failures, finite BND bounds, recovery, oracle, DR, and PR boundary have independent readiness review.
- No unqualified provider/effect path is reachable and configuration cannot widen authority.

## Definition of Done

- Immutable inputs validate and stale, malformed, ambiguous, oversized, cross-scope, or self-attested facts fail closed.
- Intent precedes every effect; uncertain effects reconcile by stable identity and retry only after confirmed absence plus recorded reauthorization.
- Exact unit, contract, negative-authority, adversarial, replay, crash/timeout/recovery, provider-or-scripted, and E2E evidence passes; git diff --check, repository checks, CI, and independent exact-candidate review pass.

# GF-020 — Qualified structured-file Work Source provider

## Outcome, value, and why now

Qualify one strict structured JSON-file realization of GF-019. It releases only a configurable
source after current exact proof and leaves other formats, fallback discovery, Run creation, and
dispatch impossible.

## Governing paths and stable IDs

`PORT-SOURCE` implements the fixed `ID-SOURCE-REQ` exchange. `FC-INPUT` covers invalid file facts,
`FC-MECHANISM` access/deadline faults; `BND-RETRY`, `BND-WAIT-MECHANISM`, and
`operation_or_source_retry` retain one bounded identity. `CF-MECH-SOURCE`, `CF-ENVELOPE`, and
`CF-GATE-PROVIDER` prove realization and admission. `DR-5`/`DR-12` retain their fixed delegation.
`PC-README-3`, `PC-JIG-1`, `PC-JIG-2`, `PC-JIG-3`, `PC-JIG-7`, `PC-JIG-13`, `PC-JIG-15`,
`PC-JIG-19`, `PC-JIG-22`, `PC-JIG-23`, `PC-CONCEPTS-1`, `PC-CONCEPTS-9`, and `PC-USE-5` map exact
source configuration, boundary, and replaceability proof. `CFG-1`, `CFG-2`, `CFG-3`, `CFG-4`,
`CFG-5`, `CFG-6`, `CFG-7`, `CFG-8`, `CFG-9`, `CFG-10` retain owner configuration semantics;
`STACK-1`, `STACK-2`, `STACK-3`, `STACK-4`, `STACK-5`, `STACK-6`, `STACK-7` require portable,
swappable, attested, authority-bounded, no-shortcut, compatible provision; `DRIVE-1`, `DRIVE-2`,
`DRIVE-3`, `DRIVE-4` bind the supported initial drive route without broadening the semantic port.

## Dependencies plus start evidence

GF-019's merged semantic contract is the `semantic-to-provider` implementation edge; GF-022's
current manifest/admission proof is the evidence edge. Verify exact provider/build/environment/
resource scope and no prior enabled source in the externally recorded execution base/tuple. A fixture pass, proposal
approval, or an unapproved/stale proof does not permit construction.

## In-scope and non-goals

One bounded JSON file format, source revision/cursor/provenance realization, and its qualification
are in scope. YAML, legacy guessing, multi-file discovery, setup, manifest approval machinery,
policy, preview, intake, and all effect paths are excluded.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The Builder's outbound `PORT-SOURCE` adapter accepts only the validated request and returns source
facts for the existing validator. It is selected only by the current qualified provider admission;
it writes no authority fact and cannot approve, transition, publish, decide, create a Run, or
dispatch. Gate evidence is proof, not a grant.

## Observable success and terminal outcomes

Success is a current proof-bound file exchange whose canonical bytes, item, revision/cursor,
digest, and provenance pass GF-019. Parse/access/drift/time-bound failure is typed exchange
failure/unavailable, not a Story outcome. The adapter releases only candidate input and cannot
create an acknowledgement, Run, lifecycle state, or effect.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Use `FC-INPUT` for invalid bytes/binding and `FC-MECHANISM` for a source access fault or deadline.
`EP-SOURCE` owns `BND-WAIT-MECHANISM`: it starts with the immutable `ID-SOURCE-REQ`, request basis,
and deadline, uses the 15-minute default within 5 seconds–2 hours, and wakes only on a validated
source result or recorded failure. It never renews. A failed, timed-out, or proved-absent attempt
consumes `BND-RETRY`, whose three-attempt default and 1–5 range never reset and whose every attempt
retains the same request identity. Exhaustion leaves the provider unavailable and fails proposal/
composition before any Run; it cannot create a Story block or acknowledgement.

Re-read the same request/revision on a lost response. Only confirmed absence plus recorded
reauthorization permits the next bounded attempt; changed bytes/revision make a new candidate, and
unknown completion is never retried blindly. Recovery rechecks exact manifest/gate/proof and the
recorded request/deadline/attempt lineage. There is no allocation, cleanup, or source session to
resume into runtime authority.

## Security and trust: validation, credentials, redaction, and authority widening

Allow only manifest-scoped canonical regular files; reject traversal, symlink escape, TOCTOU,
oversize/depth/duplicate/unknown JSON, and unverifiable provenance. Resolve read authority only in
memory; redact paths/payloads to identity/digest evidence. File data, proof, config, and fallback
cannot widen authority. Construction guard keeps this adapter unreachable until its gate is current.

## Deliverables without delegated algorithm invention

Deliver strict adapter, scoped configuration guard, hostile probes, and exact gate evidence.
`DR-5` owner **Configuration** selects this provider only after admission; fallback is omission.
`DR-12` owner **Engineering + configuration** realizes only the fixed exchange; fallback is
unavailable. Any proposed realization or configuration selection requires exact external owner
ratification/activation; Arye owns widening. No format inference is delegated.

## Test and evidence obligations

Run semantic vectors on real files; revision/change, path/symlink/permission/TOCTOU/size, timeout,
replay/recovery, stale manifest/proof, pre-gate unreachability, and no-authority probes. Record
provider/build/environment/resource, files/corpus, bounds, candidate, suite/probe versions for all
three named suites. Effect E2E is excluded because the port produces source facts only.

## Exact acceptance

Independent review requires exact adapter/configuration/manifest/gate and probe package, target
basis, evidence and delivery metadata, and no unresolved findings. Acceptance is not landing or
permission to expose a stale provider; exact merge/CI proof remains separate.

## DR choices

`DR-5`: **Configuration**, strict JSON file after current gate, exact scope/proof constraints,
unavailable fallback. `DR-12`: **Engineering + configuration**, fixed source exchange, suite
evidence, unavailable fallback. Arye must approve widening or a new plan.

## PR boundary, relative size, and split

`M`: one real source mechanism oracle. It is the required GF-019 semantic-to-provider realization;
it cannot be combined with admission or a second source family.

## Definition of Ready

- GF-019 and GF-022 merge evidence, exact manifest/proof tuple, and externally recorded execution tuple are current.
- Mapped IDs/routes/imports, failure/bounds, port authority, and gate are named.
- The adapter is structurally unreachable before qualification.

## Definition of Done

- Strict realization binds the existing semantic contract and fails closed on uncertainty.
- Required hostile, replay, timeout, authority, and gate evidence passes.
- Exact review, required checks/CI, and `git diff --check` pass before configurability.

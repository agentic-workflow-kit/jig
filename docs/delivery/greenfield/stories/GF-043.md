# GF-043 — Serialized finalizer and target authority

## Outcome, value, and why now

Give exactly one comparator-least Accepted Story per target durable finalization grant, target-basis/anchor authority, finite refresh, and mandatory re-review after Candidate change. It needs registry, recovery, capacity/bounds, acceptance, verify semantics; it never publishes/merges/lands/releases, which GF-044 owns.

## Governing paths and stable IDs

Concurrency/finalization owns one target authority, comparator, release/recovery, and no release except confirmed landing. Forge/landing owns lineage anchor and no effect before anchor. Listed IDs map finalizer, registry/target/grant, capacity/bounds/wakes, target facts, and CF-ORDER/CF-FENCE/CF-CAPACITY.

## Dependencies plus start evidence

Require merged current GF-012/015/031/032/040/042 and freeze target/registry realization, comparator priority-ordinal-Story ID, capacity reservation, accepted package/Candidate/basis, policy, rule surface, target observation. Changed package/basis/policy/rule/registry invalidates start; no real delivery provider/merge exists.

## In-scope and non-goals

Scope is queue/admit, grant/rebind/release, target/anchor observation, fence, refresh and Candidate-changing re-review, recovery. Exclude publication, acceptance, checks, request/publish/merge/status/comment, content comparison/landing/release, provider configuration, retirement. Anchor is scripted authority contract only; real effect is GF-044/GF-061.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

RT-REGISTRY is witnessed grant source; controller/CP-FINALIZER alone proposes target intents; scheduler supplies RC-FINALIZER; PORT-DELIVERY returns scripted facts. Inputs bind Accepted package, target/registry, comparator/reservation, Candidate/basis, policy, ID-AUTH, generation/fence, anchor. Ledger/registry write queue/grant/rebind/release/refresh/wake/invalidation before dispatch. Only scoped current holder acts; no worker/reviewer/provider/projection/old holder crosses Story/target/basis/registry/generation fence.

## Observable success and terminal outcomes

Success is one witnessed current grant for comparator-least eligible Story matching lineage and exact basis; others wait without power. Moved target Refreshes; Candidate change releases grant, creates successor basis/Candidate, returns GF-040 review. Conflict/indeterminate wait/park; exhaustion blocks; refusal rejects; missing predecessor NotRun; suspension preserves. No Land/release is possible.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Wrong/stale grant/anchor/cross target is FC-AUTHORITY, FC-FENCE, or FC-SUBJECT; bad fact FC-EVIDENCE; capacity FC-CAPACITY; expiry FC-BOUND. Record grant/intent first. Reobserve uncertain anchor: same registry succeeds, other parks, only confirmed absence plus reauthorization retries. Bounds are finite. Recovery rebuilds registry then authority/anchor/target before resume; release preserves Candidate/evidence; GF-046 cleans.

## Security and trust: validation, credentials, redaction, and authority widening

Validate IDs/digests/order/capacity/generation/anchor against witness; unknown/stale/cross-scope fails. Target/provider fact is evidence not grant. Credentials are named provider-memory refs; redact correlation/target metadata and quarantine hostile input. Fixture is non-configurable; no adapter gains observe/authority before qualification.

## Deliverables without delegated algorithm invention

Deliver grant/queue/fence state, target/anchor schemas, refresh/rebind/re-review transitions, fixture, recovery matrix, CF catalog. DR-3 is immutable comparator/grant tables with permutation proof/reject gaps. DR-9 is validated capacity ranges/boundary proof/preflight reject. Different ordering/authority/refresh needs owner decision.

## Test and evidence obligations

Unit/schema grant/queue/anchor/refresh/release; contract registry/target scope; negative authority stale/duplicate/cross/reviewer/provider; adversarial ties/races/policy-rule changes/hostile facts/starvation; crash/recovery/timeout every boundary. Scripted E2E proves order/refresh/re-review but no landing. Record CER/build/registry/manifest/environment and run three CF suites.

## Exact acceptance

Independent review freezes Candidate plus comparator/capacity, witness/grant, ID-AUTH fence, Accepted/verify binding, anchor facts, refresh/review trace, failures/bounds/CER. PASS proves serialization only, not target permission/provider/landing; GF-044 needs authoritative content proof.

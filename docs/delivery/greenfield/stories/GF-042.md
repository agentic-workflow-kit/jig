# GF-042 — Effect-free verification semantic contract

## Outcome, value, and why now

Define exact-subject, enforced effect-free PORT-VERIFY and scripted fixture for frozen deterministic checks, so a lost observation is replaced under a new operation identity. It cannot choose check classes/sufficiency/posture, accept, mutate, land, or configure a verifier; GF-047 separately qualifies local command execution.

## Governing paths and stable IDs

Review execution owns declarative `RP-CHECKCLASS`, `RP-VERIFY`, clean checkout, and the
read-only/scratch/no-egress effect-free contract. `PORT-VERIFY`, `OPC-VERIFY-EXECUTE`, and
`EV-CHECK-OBSERVATION` identify the local contract; `RT-CONTROLLER` authorizes it;
`FC-SUBJECT` rejects a wrong candidate/basis; `CF-MECH-VERIFY` proves effect-free realization; and
`CF-POLICY` proves configuration cannot weaken required classes. `RP-FINDING`,
`RP-INDEPENDENCE`, `RP-PACKAGE`, `RP-PACKAGE-DIGEST`, and `RP-VERDICT` are input bindings from the
accepted review package, not verification outputs. `PC-JIG-8`, `PC-CONCEPTS-3`, and `PC-JIG-10`
carry independent review and frozen-policy commitments; `EARN-1`/`EARN-2`, `GUARD-1`/`GUARD-2`,
`MERGE-1` requires independent policy-aligned evidence; `MERGE-2` reserves push, PR creation, and
merge to the runner; `MERGE-3` makes done conditions policy-bound; `MERGE-4` separates done from
merged; and `MERGE-5` requires safe Blocked-work surfacing.

`ID-OP` is the immutable identity of one authorized verification attempt, including a replacement
after a lost result; `ID-CAND` names the exact Candidate whose content and basis the check observes.

## Dependencies plus start evidence

Require GF-004 harness, GF-015 operation semantics, GF-021 policy binding, GF-022 manifest admission, and GF-035 Candidate observed in this story's execution base/tuple. Freeze Candidate/basis, Accepted fixture, policy required-class declaration, configuration binding, clean receipt, manifest, and fixture versions. `baseline_commit` remains immutable planning/authority provenance, not the execution base. Omitted/unknown/unbound required class fails preflight; fixture is non-configurable until GF-047 gate and any real verifier realization additionally requires the external activation record in `decisions.md`.

## In-scope and non-goals

Scope is execute/retrieve a named frozen local check class against exact Accepted Candidate. Exclude remote-gate observation or execution, policy authoring/sufficiency, verdict/rework decision, mutation, workspace provisioning, external effects, finalization/landing, and provider configuration. Remote gates are delivery facts on PORT-DELIVERY in GF-044. Effect-needing checks are separately authorized workspace/delivery work or rejected.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

Controller/mediator authorizes OPC-VERIFY-EXECUTE through PORT-VERIFY; ledger records intent/observation. Request binds ID-OP, Candidate/basis, class/configuration, environment, clean receipt, and fence. EV-CHECK-OBSERVATION binds pass/fail, bounded redacted artifacts, provider/build/manifest/environment/time. Verifier observes only; it cannot choose policy, accept, rework, mutate, or dispatch. Capability fences read-only checkout, discarded scratch, zero egress.

## Observable success and terminal outcomes

Success is durable subject-matching observation for every frozen required class. Required fail returns to GF-035 bounded rework and releases held finalizer; posture none dispatches nothing. Wrong/effectful/unbound input is FC-SUBJECT or FC-AUTHORITY, invalid evidence FC-EVIDENCE, mechanism fault FC-MECHANISM; required check or rework exhaustion blocks. Only exact Story-bound owner reject-story yields Rejected, and only direct Blocked/Rejected dependency yields Pending NotRun; missing input/start/provider does neither. Run Stopped is overlay-only. It cannot Accept/Land/release.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Intent is durable first. Lost/replaced result gets new authorized ID-OP, never reused uncertain proof. BND-WAIT-MECHANISM expiry parks a missing/indeterminate local observation; required check or rework exhaustion blocks. Write/network/mutation assertion, stale fence, ambiguity fails closed and preserves Candidate. Recovery validates intent/receipt/observation; scratch discards only after safe adoption/abandonment; timers wake only.

## Security and trust: validation, credentials, redaction, and authority widening

Canonicalize/limit class/basis/environment and enforce digest equality, read-only paths, discarded scratch, no egress. Reject escapes, undeclared env, effects, cross-Candidate/stale/forged result, and secret/oversized output. Credential names resolve only in provider memory; fixture uses none; redaction/quarantine applies. Results never mint policy, acceptance, target, or delivery authority.

## Deliverables without delegated algorithm invention

Deliver versioned request/observation schemas, capability fence, guards, scripted local verifier, evidence admission, and CF fixtures. DR-4 Engineering + configuration proposes typed in-process port/edge transport with exact-subject/effect-free constraint, CER proof, and unavailable fallback; any realization requires the external activation record in `decisions.md`. No policy or command-selection algorithm is delegated.

## Test and evidence obligations

Unit/schema canonical values; contract exact echo/read-only/replacement/none; negative authority rejects effect/network/write/accept/land; adversarial rejects unbound class, changed subject, stale proof, forged gate, hostile output; replay/crash/timeout covers intent/lost result/restart. Scripted E2E proves pass/fail affects rework not acceptance/landing. Record CER/build/manifest/environment/fixture/probes and run both CF suites.

## Exact acceptance

Independent review freezes implementation Candidate, schemas, fence, fixture, policy/config binding, vectors, failure/bound/recovery evidence, and CF CERs. PASS admits semantic contract only, not configured verifier; runtime Candidate needs GF-040 and GF-044 alone lands.

## DR choices

DR-4: Engineering plus configuration, typed semantic port, effect-free exact-subject proof, mechanism suite, unavailable fallback. DR-5 inapplicable: GF-047 owns provider selection/qualification.

## PR boundary, relative size, and split

M; one deterministic effect-free observation oracle. Include schemas, guards, fixture, tests; exclude command provider/workspace/review/landing. Required split is GF-042 semantic to GF-047 provider.

## Definition of Ready

- All named predecessor commits and exact-subject evidence are observed and bound in this story's execution base/tuple; `baseline_commit` remains planning/authority provenance.
- Governing IDs, port, principal, fence, durable facts, typed failures, finite bounds, recovery route, oracle, DR record, and PR boundary have independent readiness review.
- Unqualified providers/effect paths are unreachable and configuration cannot widen authority.

## Definition of Done

- Versioned immutable inputs validate and stale, malformed, ambiguous, oversized, cross-scope, or self-attested facts fail closed.
- Intent precedes every effect; uncertain effect is reconciled by stable identity and only confirmed absence plus recorded reauthorization permits same-effect retry.
- Required unit, contract, negative-authority, adversarial, replay, crash, timeout/recovery, provider-or-scripted, and E2E evidence is exact-subject-bound; git diff --check, repository checks, CI, and independent exact-candidate review pass.

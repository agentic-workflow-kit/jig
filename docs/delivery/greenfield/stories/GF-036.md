# GF-036 — Doorbell decisions and delegation

## Outcome, value, and why now

Provide durable Doorbell request/answer, authenticated owner decisions and scoped per-Run delegation. It requires GF-015 effect certainty, GF-030 lifecycle, GF-034 session seam and GF-035 exact assignments. It enables parked work and later obligations; it does not provide pre-Run approvals, automatic responders, acceptance, delivery, Run suspend/resume/stop or landing.

## Governing paths and stable IDs

D14 owns the human-needed seam and says provider native allow/reject is not Jig authority. operations-and-observability.md and catalogue own PORT-DECIDE, SCH-ESCALATION, SCH-DELEGATION-GRANT, SCH-DECISION, ID-PARK/ID-GRANT and response operation. BND-WAIT-DECISION is finite; DR-4 does not delegate authority design.

### Track mapping

PORT-DECIDE authenticates owner/current delegate; SCH-ESCALATION is durable Doorbell request; SCH-DELEGATION-GRANT is narrow per-Run grant; SCH-DECISION is exact response; ID-PARK and ID-GRANT identify request/grant; BND-WAIT-DECISION bounds answer; RT-CONTROLLER records lifecycle effect; EV-SESSION-HUMAN-REQUEST, EV-OWNER-DECISION and EV-DELEGATION-GRANT are request/answer/grant events; OPC-SESSION-RESPOND returns answer to exact binding; ID-PRINCIPAL is authenticated actor; FC-AUTHORITY rejects invalid proof; CF-OPERATOR-ACTIONS, CF-DELEGATION and CF-PROVIDER-PERMISSION prove limits; human_decision is track coverage token. Product routes PC-JIG-5 is operator/delegation, PC-JIG-6 operator/control, PC-JIG-9 and PC-USE-2 permission/session, PC-USE-7 rule/operator proof. EARN-1 fresh proof and EARN-2 context specificity restrict autonomy; GUARD-1 frozen policy and GUARD-2 changed safety rule reapproval apply; DOOR-1 common Doorbell, DOOR-2 durable escalation and DOOR-3 narrow grant are exact commitments.

## Dependencies plus start evidence

Require merged GF-015 operation/reconciliation, GF-030 Parked transition, GF-034 authenticated session request/principal lineage and GF-035 current assignment/candidate binding. Start evidence records exact principal authentication/trust root, request/grant schema, predecessor commits/tree/evidence, externally recorded execution base/tuple and CI/reviewer proof. Provider internal approval or a UI message is not a decision.

## In-scope and non-goals

Scope: request, routing, answer, grant/revoke/expiry and response intent. Exclude policy/envelope approval, run control events (GF-037), automatic middleman, provider command sandbox, acceptance/delivery and obligation lifecycle realization. A grant is per-Run, exact scope, time/bound and action constrained.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

CP-ESCALATION validates attributable session request then writes SCH-ESCALATION/ID-PARK; PORT-DECIDE accepts authenticated owner or current exact delegate answer and writes SCH-DECISION. SCH-DELEGATION-GRANT/ID-GRANT binds grantor, delegate principal, Run, request/action scope, start/expiry/revocation and generation. Controller alone parks/resumes/responds; owner decides, delegate only within grant; provider only consumes scoped response. Exact principal, request, assignment and grant fence prevents provider, stale delegate or another session deciding.

## Observable success and terminal outcomes

A valid question becomes durable Parked with accountable responder/wake; valid scoped answer deterministically continues, blocks or stays state-neutral and returns one response to currently bound originating principal/assignment. Attested-loss replacement is same-principal lineage; unrestorable context closes named request and reissues successor. Invalid/expired/delegated-outside-scope answer fails closed. No provider answer changes posture, authorizes Operation, rejects Story, accepts or lands.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Bad auth/schema FC-INPUT/FC-AUTHORITY; wrong request/principal FC-SUBJECT; stale grant/generation FC-FENCE; deadline exhaustion FC-BOUND and durable re-escalation under BND-WAIT-DECISION. Response effect records ID-OP before dispatch; uncertain response reconciles and is never blindly resent. Recovery rebuilds live request/grant then preserves/parks. Grant expiry/revocation preserves request; later residual duty is GF-038.

## Security and trust: validation, credentials, redaction, and authority widening

Authenticate exact owner/delegate principal against configured trust root, validate canonical scope/action/Run/request/grant/fence and bounded answer. Credentials stay in memory; redact answers/secrets in logs/evidence. Provider facts and fallback never widen grant. Missing/stale/ambiguous proof fails closed; unqualified provider cannot route a request.

## Deliverables without delegated algorithm invention

Deliver decision/grant/escalation schemas, authenticated PORT-DECIDE contract, request/answer/grant lifecycle, scripted fixtures and CF evidence. Engineering plus configuration own DR-4; D14's approved human-needed, per-request and no-middleman constraints are immutable. Standing delegation/provider lifecycle authority rejected; widening/change is OWNER_DECISION_REQUIRED for Arye Kogan; blast radius GF-037/GF-038/operability.

## Test and evidence obligations

Test owner/delegate authentication, exact scope/expiry/revocation, wrong principal/request, provider non-authority, session replacement/cancel-reissue, response idempotency/uncertainty, timeout/re-escalation, crash/replay. Record trust/grant/request/answer/operation/candidate/tree digests, witness and runner. CF-OPERATOR-ACTIONS, CF-DELEGATION, CF-PROVIDER-PERMISSION required.

## Exact acceptance

Independent reviewer checks exact decision package, principal/grant evidence and all findings. Phase-3 evidence verdict only; GF-040 acceptance/GF-044 landing unavailable. Self-authored or differently bound answer fails closed.

## DR choices

Engineering plus configuration own DR-4. Automatic responder, new scope/action or provider authority is a widening/change requiring Arye Kogan's owner decision.

## PR boundary, relative size, and split

Size L; one authority oracle is exact request-to-principal-to-answer lineage. Paths: schemas/port/controller/fixtures/CF; UI/provider implementation excluded. Split Doorbell/grant only behind one envelope and fence.

## Definition of Ready

- GF-015/GF-030/GF-034/GF-035 merged with exact request, session and candidate facts.
- Principals, authority, durable facts, bounds, failure/recovery and CF suites explicit.
- DR-4/D14 recorded; no automatic responder.

## Definition of Done

- Only owner/current exact delegate can decide, and response returns to exact originating principal/assignment.
- Uncertainty and expiry preserve/re-escalate; provider cannot widen authority.
- Required evidence, diff check, checks, CI and independent review pass.

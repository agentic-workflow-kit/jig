# GF-033 — Workspace semantic contract

## Outcome, value, and why now

Define PORT-WORKSPACE plus scripted fixture for stable host, workspace, basis, cleanliness, setup receipt and preservation facts. It needs GF-015 operation certainty, GF-021 frozen setup, GF-022 manifest/proof shape and GF-031 capacity. It enables GF-039 qualification, never a configured real host.

## Governing paths and stable IDs

mechanism-and-provider-contracts.md owns port direction/qualification fence; lifecycle-catalogs.md owns five OPC-WS operations and preserve-before-retire. DR-4 bounds the mediated operation contract, not provider authority or workspace algorithm.

## Dependencies plus start evidence

Require merged GF-015 certainty, GF-021 recipe/receipt/policy digest, GF-022 scripted manifest/capability-proof shape, GF-031 isolation reservation. Record all predecessor commit/tree/evidence digests and fixture version. Real-host probe or unqualified provider claim is insufficient.

## In-scope and non-goals

Scope: schemas, identity bindings, freshness/no-op, destructive ambiguity containment and scripted faults. Exclude local Git host (GF-039), remote/Windows, sessions, candidates/delivery and real cleanup config. RETIRE semantics exist but no real operation enables.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

CP-MEDIATOR records SCH-OPERATION then calls PORT-WORKSPACE. Scripted output binds host identity/build/posture, ID-WORKSPACE, basis, cleanliness, recipe/input/host fingerprints, receipt and preservation. RT-CONTROLLER validates/writes workspace/setup/preserved events to witnessed ledger. Fenced transition alone dispatches; adapter fact cannot transition, authorize session or mint capability. Operation/manifest binding fences all actors.

## Observable success and terminal outcomes

Scripted provision/observe/setup returns stable exact facts; fresh exact receipt is setup no-op, stale receipt authorizes one setup intent; preservation precedes retire. Invalid, dirty, ambiguous, destructive or unverifiable fact parks/blocks and preserves. It cannot accept, land, release or silently retire; no concrete provider configures.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Bad identity/basis FC-INPUT/FC-SUBJECT; stale FC-FENCE; adapter failure FC-MECHANISM; uncertain operation FC-EFFECT with ID-OP. Intent precedes call; retry only confirmed absence plus reauthorization, otherwise reconcile/park/preserve. Recovery reads operation/fact identity. Cleanup uncertainty retains workspace; GF-046 owns actual retire.

## Security and trust: validation, credentials, redaction, and authority widening

Validate canonical/limited values, digest/basis/host/build, cleanliness and receipt lineage. Credential names resolve only in provider memory; secrets/secret paths never ledger/evidence/export. Posture is exact provider claim, not inference. Unknown/stale/self-attested/ambiguous facts fail closed; scripted adapter is test-only/unconfigurable.

## Deliverables without delegated algorithm invention

Deliver port/schema, five bindings, scripted adapter/fault fixtures, freshness/preservation oracle and evidence metadata. DR-4 owner Arye selected mediation; operation identity, record-before-effect, exact manifest and preservation are immutable. Ambient filesystem authority/inferred freshness rejected; gap OWNER_DECISION_REQUIRED; blast radius GF-039/later workspace work.

## Test and evidence obligations

Test stable replay, wrong host/basis/cleanliness/receipt, stale/fresh setup, lost/uncertain/duplicate operation, preservation-before-retire, crash/recovery and authority negatives. Record fixture/manifest/request/result/operation/candidate/tree digests, witness and runner. CF-MECH-WORKSPACE/CF-SETUP-FRESHNESS required; real provider gate absent/configuration off.

## Exact acceptance

Independent reviewer verifies exact contract/fixture/evidence and absence of real config. Evidence verdict only: GF-040 acceptance and GF-044 landing unavailable. Partial fixture, stale manifest or self-review fails closed.

## DR choices

DR-4 applies. Host mode/filesystem policy/concrete configuration requires owner-approved DR-5 qualification.

## PR boundary, relative size, and split

Size M, one semantic port oracle. Paths: port/schema/scripted fixture/tests/CF; local host excluded. Do not split contract from fixture unless jointly testable; GF-039 is concrete provider.

## Definition of Ready

- GF-015/021/022/031 merged with setup, manifest and reservation proof.
- Facts, writer, authority, recovery and CF suites explicit.
- DR-4 fixed; only scripted adapter reachable.

## Definition of Done

- Stable facts and fail-closed freshness/preservation work.
- Uncertainty reconciles or preserves; no real provider configures.
- Contract/fault/recovery evidence, diff check, checks, CI and independent review pass.

# GF-020 — Qualified structured-file Work Source provider

## Outcome, value, and why now

Make one structured JSON-file source configurable only after the exact GF-019 semantic contract,
owner-approved manifest admission, and real-provider `CF-MECH-SOURCE` evidence pass. It supplies
the initial local product route without granting source authority. Other formats, inference, and
fallback remain unavailable.

## Governing paths and stable IDs

`mechanism-and-provider-contracts.md` fixes repeatable source identity, bounded retry and
reconnection behavior; `envelope-production.md` fixes `EP-SOURCE` validation and changed-content
semantics; `delegation-register.md` constrains `DR-5` and `DR-12`. `PORT-SOURCE` is the only seam;
`CF-MECH-SOURCE` and `CF-GATE-PROVIDER` prove this concrete realization, not provider authority.

## Dependencies plus start evidence

Require merged GF-019 exact contract/corpus evidence and GF-022's current exact manifest approval,
qualification registry, and provider-admission evidence for this provider/build/environment/scope.
Verify both on the selected baseline and verify no other source is enabled. A plan fixture pass,
proposal approval, or a manifest without current real-provider evidence does not satisfy either
edge.

## In-scope and non-goals

In scope: one explicitly versioned structured JSON file format and file realization of the existing
source exchange, including file bytes/revision/cursor/provenance and real-provider qualification.
Exclude YAML, legacy/multi-file discovery, arbitrary path search, policy/profile composition,
manifest approval mechanics, capability proofs, preview, intake, setup execution, and any Run.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The configured adapter is an outbound realization of Builder `PORT-SOURCE`; it receives only a
validated `ID-SOURCE-REQ` and returns `SCH-SOURCE-EXCHANGE` facts. Configuration selects it only
through the admitted exact `ID-MANIFEST`/build/resource scope. It persists no authority and cannot
approve, write ledger records, create a Run, dispatch, or select a different provider; Builder
validation remains authoritative. Qualification evidence is durable gate evidence, not a grant.

## Observable success and terminal outcomes

Success is the exact file provider returning stable canonical plan bytes, item/revision/cursor,
content digest, and provenance that GF-019 accepts, with current gate evidence. Missing, malformed,
changed-during-read, noncanonical, wrong-scope, stale-evidence, timeout, exhausted, or
unreconciled results are pre-Run `Rejected`/unavailable. It releases only source input; it cannot
produce approval, `ID-RUN`, transition, Operation, or dispatch.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Parse/identity faults are `FC-INPUT`/`FC-SUBJECT`; file access/deadline faults are `FC-MECHANISM`;
manifest/gate mismatch is `FC-AUTHORITY`. Retain the same request identity under immutable
`BND-WAIT-MECHANISM` and `BND-RETRY`; retry only a confirmed absent/read-uncompleted exchange and
record the basis/ordinal. Lost/partial read is reconciled by re-reading the exact request and
revision/cursor; mismatch or changed bytes is a new candidate, never a blind retry. Recovery
revalidates manifest and evidence before reuse; no provider allocation needs cleanup and no source
session may resume into a Run.

## Security and trust: validation, credentials, redaction, and authority widening

Allow only manifest-scoped canonical paths and regular bounded files; reject symlinks/escapes,
TOCTOU revision mismatch, oversized/deep/duplicate/unknown fields, untrusted provenance, and
ambiguous encodings. Resolve only the approved read capability in memory; log/evidence retains
redacted path class and digests, never secrets. File contents remain candidate data and cannot
widen policy or authority. Construction/configuration gates deny the adapter until matching
owner-manifest approval and current exact qualification evidence are both admitted.

## Deliverables without delegated algorithm invention

Deliver one JSON-file adapter, hardened parsing/revision observation, manifest-scoped configuration
entry, provider probe suite, and gate evidence. `DR-5` owner Configuration selects this initial
provider only inside manifest/posture/conformance constraints; exact gate evidence is required and
fallback is unavailable. `DR-12` owner Engineering/configuration realizes this channel without
altering exchange semantics; `CF-MECH-SOURCE` is evidence and rejection is fallback. No heuristic
format recognition or provider semantics may be invented.

## Test and evidence obligations

Execute GF-019 contract vectors against real files; valid/revision/cursor/changed-content probes;
hostile JSON/path/symlink/permission/TOCTOU/size corpus; timeout/retry/lost-read/restart cases;
manifest/build/environment mismatch and pre-gate unreachability tests; and negative authority tests
for Run/ledger/dispatch. Record provider/build/manifest/environment/resource, corpus and file
identities/digests, suite/probe results, bounds, and exact candidate in `CF-MECH-SOURCE` and
`CF-GATE-PROVIDER`. E2E stops at source exchange because intake is out of scope.

## Exact acceptance

Independent review receives the exact adapter/configuration digest, approved manifest binding,
provider/build/environment/resource basis, full real-provider probe evidence, gate result, and
candidate/target delivery metadata. It requires all relevant findings resolved and an exact-current
gate; proposal approval or self-authored evidence cannot replace it. Acceptance is not landing;
merged/CI exact-candidate proof remains separate.

## DR choices

- `DR-5` — Configuration; structured JSON file is selected after qualification only; immutable
  manifest/gate rules remain; gate evidence proves it; absent evidence leaves it unconfigurable.
- `DR-12` — Engineering/configuration; one strict channel realization; immutable request/exchange
  contract remains; `CF-MECH-SOURCE` proves it; reject rather than guess a format.

## PR boundary, relative size, and split

`M`, provider-only realization with one real-provider oracle. Expected paths are adapter,
manifest-scoped entry, provider probes, and qualification evidence. Do not combine with GF-019's
semantic core or GF-022 admission; those have independent failure domains.

## Definition of Ready

- GF-019 and GF-022 are merged with their exact contract, manifest, and admission evidence.
- Provider identity/build/resource/authority, bounds, failures, and gate are named.
- `DR-5`/`DR-12` remain bounded and pre-gate construction is impossible.
- The independent reviewer has an exact provider start package.

## Definition of Done

- Strict bounded JSON parsing and stable source binding reject unknown/changed/unsafe input.
- Retry/recovery is bounded and reconciled; the adapter has no authority or effect path.
- Real-provider hostile, replay, timeout, gate, and negative-authority proof passes.
- `CF-MECH-SOURCE`, gate evidence, exact checks/CI/diff, and independent review pass before
  configuration exposure.

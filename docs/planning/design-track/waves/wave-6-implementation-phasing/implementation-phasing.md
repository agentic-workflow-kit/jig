# Wave 6 implementation-phasing handoff

This is a planning-track handoff for future delivery planning in the `jig` repo. It sequences the
settled design into implementation-ready phases. It is not runtime code, not a package layout, not a
schema freeze, and not a delivery tracker.

## Owner And Consumed Contracts

- **Owner repo:** `jig`.
- **Consumed and owned by Jig:** execution-plan contract and observability/event-records contract.
- **Consumed provider seams:** Agent, Execution Host, Forge, Work Source provider contracts.
- **Consumed driving seam:** driving/operator contract.
- **Consumed core design surfaces:** plan intake, records, authorization, bootstrap, orchestration,
  policy/evidence, and recovery/records design surfaces.
- **Consumed product authority:** Jig product, guarantees, concepts, and use cases where a scenario
  needs product-level grounding.

## What Wave 6 Must Not Decide

- Runtime code, TypeScript interfaces, JSON Schema, exports, package names, or package decomposition.
- Concrete provider manifests, conformance-suite schema, adapter API signatures, or source layout.
- Any `docs/design/**` change or product/design fact not already owned by current sources.
- New runtime states, event strings, field names, policy classifiers, or record schemas.
- New hard-numbered `INV-*` rows, including `INV-019`.
- U9 traceability collection, red-team collector work, or future delivery tracker execution.

## Cross-Repo Seams And Dependency Direction

- `design-to-plan` may produce execution plans to Jig's execution-plan contract shape. Jig validates
  the plan and must not depend on `design-to-plan` internals.
- Future Learning consumes Jig observability/event records. Learning is between-runs and must not
  enter Jig's per-run hot path.
- `define-product` and `technical-design` supply upstream artifact formats or product/design IDs
  through contracts and citations. Jig must not depend on their implementation internals.
- Provider packages implement behind Jig provider contracts. Providers supply claims and mechanics;
  Jig core judges policy, evidence, authorization, lifecycle, and record semantics.

## Contract Unfrozen Proof

Wave 6 preserves both v0 contracts as cited and unfrozen:

- every phase references required contract properties, not exact field names;
- fixture examples are illustrative until a contract owner approves schema freeze;
- TypeScript interfaces, JSON Schema, event constants, exports, and provider manifests are stop
  conditions unless current design owners explicitly authorize them;
- any needed field-level change routes to the relevant contract owner instead of landing as local
  implementation convenience.

## Future Delivery Handoff

Future delivery planning should turn each phase into executable stories only after it can cite:

- source docs consumed by that phase;
- the prerequisite-triage rows it carries as stop/evidence gates;
- tests and proof artifacts required for the phase;
- exact out-of-scope boundaries, especially no runtime code outside the phase's owned proof surface;
- verification commands, with `corepack pnpm check` as the local gate unless delivery changes the
  repo's gate deliberately.

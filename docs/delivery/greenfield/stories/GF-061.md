# GF-061 — Qualified GitHub review and delivery provider

## Outcome, value, and why now

Qualify a GitHub adapter that keeps pre-acceptance draft review publication and post-acceptance
final delivery in disjoint capability/credential classes, with exact effect reconciliation. It permits
only the selected real provider profile after proof. It follows review, finalization, delivery, and
retirement semantics; it cannot turn a draft review request into target authority or make
queue/held/unknown modes configurable.

## Governing paths and stable IDs

`D15` owns bounded `PORT-DELIVERY` review-publication: exact Candidate/target/generation/ref/marker
binding, draft non-mergeable request, no `ID-AUTH`, no target mutation/finalization/landing, and
stable-marker reconciliation. `mechanism-and-provider-contracts.md` owns provider qualification.
`DR-4`/`DR-5` delegate selected configuration/mechanism only; final target effects remain proposed
by `CP-FINALIZER` and authorized only by recorded `CP-TRANSITION`.

Local mapping: `PORT-DELIVERY` is the only GitHub seam; `DR-4`/`DR-5` bound configuration/provider;
`FC-MECHANISM`/`BND-WAIT-MECHANISM` contain API fault; `EV-TARGET-FACT` and `RP-REMOTE` bind remote
target observation; `OPC-DEL-OBSERVE` is the recorded remote-observation effect; `ID-OP` binds its
stable reconciliation identity; `ID-TARGET` binds the observed target; and `ID-AUTH` is required
only for post-acceptance final delivery, never review publication. `CF-SECRET-ABSENCE`,
`CF-MECH-DELIVERY`, `CF-REVIEW-PUBLICATION`,
`CF-BLOCK-SURFACING`, and `CF-GATE-PROVIDER` prove admission. `PC-JIG-8`, `PC-JIG-11`, `PC-JIG-15`,
`PC-JIG-21`, `PC-CONCEPTS-3`, `PC-CONCEPTS-5`, `PC-CONCEPTS-6`, and `PC-USE-5` close only through
disjoint real review/final capabilities. `MERGE-1`, `MERGE-2`, `MERGE-3`, `MERGE-4`, `MERGE-5`,
`SEC-1`, `SEC-2`, `SEC-3`, `STACK-1`, `STACK-2`, `STACK-3`, `STACK-4`, `STACK-5`, `STACK-6`,
`STACK-7`, `DRIVE-1`, `DRIVE-2`, `DRIVE-3`, and `DRIVE-4` close through exact remote reconciliation,
credential separation, and delivery evidence.

## Dependencies plus start evidence

Require exact merged GF-022 provider authority, GF-041 review publication, GF-043 target authority,
GF-044 delivery/reconciliation, and GF-045 block/retirement evidence. Freeze GitHub API/build,
provider manifest, repository/target basis, review and final credential references/scopes, branch
protection/mode, stable marker format, selected host/environment, and predecessor suite digests.
Any absent/stale/substituted proof, held/queue mode, or permission overlap leaves provider unavailable.

## In-scope and non-goals

In scope: real adapter qualification for exact draft review ref/request/status/comment/retirement and
authorized final delivery/readback/retirement effects with separate credentials. Exclude worker or
reviewer forge credential access, pre-acceptance target write/merge, generic GitHub automation,
merge-queue/held mode support, public API surface, credential sharing, and policy/acceptance changes.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The adapter mediates `PORT-DELIVERY` facts/effects. Every review action binds Candidate content digest,
target basis, controller generation, dedicated ref, draft request identity, provider manifest, and
stable marker; it omits `ID-AUTH`. Every final action additionally requires the recorded finalizer
proposal/Transition authorization, exact `ID-AUTH`, and exact `ID-TARGET`. Durable `ID-OP` operation
intent, effect identity,
marker, observed ref/request/target state, receipt/failure, candidate delivery metadata, and
retirement obligation are truth. Review credential can create/update draft non-mergeable review
objects only; final credential has only selected final effect scope; neither is given to worker or
reviewer. GitHub observations cannot declare acceptance/landing or release dependencies.

Remote delivery evidence is not local-verifier evidence: the adapter dispatches the recorded
`OPC-DEL-OBSERVE` through `PORT-DELIVERY`, validates an exact `RP-REMOTE` observation against the
Candidate/target/manifest/fence, and commits `EV-TARGET-FACT` before any landing conclusion. The
local verifier remains solely under `PORT-VERIFY`; neither it nor a GitHub response owns delivery.

## Observable success and terminal outcomes

Success is current-profile GitHub evidence showing an exact draft non-mergeable review publication
before acceptance and exact final effect/readback only after authority/Transition gates. Every external
effect is idempotent or discoverable by its stable marker. Review publication/status/comment never
changes target/anchor/finalization/landing. Unknown/held/queue/ambiguous results are `Blocked` or
`Parked` according to existing containment and retain authority fence; no `Landed` occurs without
authoritative target proof.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Map malformed, unknown, noncanonical, oversized, or version-skew Candidate/ref/marker input to
`FC-INPUT`; wrong Candidate/ref/path/target subject to `FC-SUBJECT`; stale controller/authority fence
to `FC-FENCE`; scope breach to `FC-AUTHORITY`; invalid remote proof to `FC-EVIDENCE`; GitHub/API
timeout/fault to `FC-MECHANISM`; observed conflict/unknown effect to `FC-EFFECT`; and named wait
exhaustion to `FC-BOUND` at `BND-WAIT-MECHANISM` or `BND-WAIT-TARGET`. Record each exact review or
delivery Operation intent before
dispatch. Reconcile exact effect via stable marker plus API observation of ref/request/target and
record certainty before any repeat; only confirmed absence plus reauthorization permits same identity
retry. Recovery rereads durable operation/authority facts, fences stale generation/results, retains
draft clutter as retirement duty/`ID-OBLIGATION`, and preserves on uncertain cleanup. No provider
reconnect resumes an unauthorized final effect.

## Security and trust: validation, credentials, redaction, and authority widening

Canonicalize repository/ref/target/marker/Candidate digest, validate API response binding and current
manifest, and enforce credential-class disjointness in configuration and runtime. Review and final
credential names resolve in memory only with least scopes; secrets/tokens/raw headers are excluded
from ledger/evidence/export/logs. Redact review content/provider metadata as policy requires.
Unverifiable API result, mode, scope, or proof fails closed. No GitHub response, draft request, or
fallback can mint `ID-AUTH`, acceptance, finalization, or landing authority.

## Deliverables without delegated algorithm invention

Deliver private GitHub provider adapters, separate credential/profile validators, exact marker/ref
mapper, review/final effect reconcilers, mode gate, retirement/obligation bridge, sandbox repository
fixtures, and qualification recorder. `DR-4` is implemented by Engineering + configuration and
`DR-5` by Configuration; Arye approves the recorded profile or any widening. Constraints are D15 and
credential separation; evidence is real matrix; fallback is provider unavailable.
New mode, scope, merge policy, or credential model is `OWNER_DECISION_REQUIRED`.

## Test and evidence obligations

Run real sandbox-repository tests for review/final credential disjointness, draft/non-mergeable/no-
target-change review operations, exact Candidate/target/marker binding, finalizer/Transition
prerequisites, idempotent discover/reconcile matrix, timeout/API failure/unknown outcome, stale
generation, cancellation, crash/recovery, retirement obligation, hostile response, secret absence,
and held/queue rejection. Require `CF-MECH-DELIVERY`, `CF-REVIEW-PUBLICATION`,
`CF-BLOCK-SURFACING`, and `CF-GATE-PROVIDER` with exact build/manifest/repo/mode/fixture/output
digests. Landing E2E is included only for authorized sandbox target proof, never by GitHub assertion alone.

## Exact acceptance

Independent reviewer receives exact candidate/target/provider/credential-class/mode digests, redacted
real-provider evidence, marker reconciliation traces, and suite results. Any credential overlap,
mergeable draft, target effect before gate, unreconciled uncertain effect, or enabled held/queue mode
fails. Acceptance is not the authoritative merged landing proof.

## DR choices

`DR-4` implementation owner is Engineering + configuration and `DR-5` implementation owner is
Configuration. Arye approves the recorded GitHub review/final profile and any widening. The fixed D15
boundaries, real evidence, provider-unavailable fallback, and delivery-mechanism blast radius apply.
Rejected alternatives are shared credential, worker publishing, landing-capability reuse, or
queue/held support. No new DR applies.

## PR boundary, relative size, and split

L, one provider qualification but two independently privileged mechanism families. Split GF-061a
draft review publication and GF-061b final delivery if their credential/evidence gates cannot be
reviewed under one exact oracle; GF-061a stays unable to target-change or land.

## Definition of Ready

- Dependencies, GitHub profile/mode/credential classes, stable markers, target basis, and exact gate fixtures are current.
- D15 authority exclusions, effects/bounds/reconciliation, redaction, retirement, and DR fallbacks are explicit.

## Definition of Done

- Review/final credentials are structurally disjoint; every external effect is exact-bound and reconciled before retry.
- Required real-provider, authority, fault, timeout, recovery, retirement, secret, and gate evidence passes.
- Exact independent review, `git diff --check`, repository checks, CI, and authoritative landing proof pass.

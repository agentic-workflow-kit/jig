# GF-010 — Witnessed conditional Run ledger

## Outcome, value, and why now

Deliver the Run-domain `PORT-LEDGER` contract and its selected segmented, append-only file reference realization. It gives `CP-TRANSITION` a durable, ordered, conditional authority record with an independent currency witness, so later controller recovery, registry, artifacts, and mediation have a trustworthy base. Registry, intake-index, artifact-pin, snapshots, backup, compaction, provider qualification, and all product effects remain impossible.

## Governing paths and stable IDs

`guarantees.md` maps this foundation to `RESUME-1`, `RESUME-2`, and `RESUME-4`: durable progress, safe checkpoint recovery, and diagnosable fail-closed stop. `persistence-and-projections.md` owns conditional append, five-way readback, chain and witness order; D11 selects the single-host fsync-on-ack file realization without making its layout canonical. `state-and-recovery.md` owns recovery and `FC-TRUST`; `runtime.md` owns `RT-LEDGER`, independent `RT-WITNESS`, and `PORT-LEDGER`; `architecture-conformance.md` owns `CF-MECH-LEDGER`. `LG-RECORD` carries `ID-TXN`, staged content digest, and prior digest; `LG-POSITION` is strictly increasing; `LG-APPEND` is expected-head conditional commit; `LG-ACK` follows durable flush and witness; `LG-READ`/`LG-CHAIN` verify. `DR-6` permits only physical technique beneath those clauses.

## Dependencies plus start evidence

Start only when GF-002's merged codec/vector evidence proves canonical identity/digest framing and GF-005's merged pure transition kernel proves the sole Run writer, `ID-TXN`, and record-before-adopt/dispatch intent shape. Select the current baseline above, record both merged commit digests and passing exact-candidate evidence, and verify the configured witness binding is a separately trusted store, not ledger storage/backups. A branch assertion, a same-host adjacent file, or an unqualified alternate backend is insufficient.

## In-scope and non-goals

In scope: one Run's authoritative chain, generation-qualified conditional append/readback, per-Run segmented file log, and one witness line per Run. Exclude registry and intake structures, artifact pin witness, snapshot policy, archive/backup, mutable projections, batching/segment size/directory algorithm, public APIs, provider configuration, and all effects. The reference adapter stays test-only/unconfigurable until its own recorded `CF-MECH-LEDGER` pass.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`RT-CONTROLLER`/`CP-TRANSITION` is sole Run-record writer; `RT-LEDGER` is passive storage and `RT-WITNESS` stores monotonic `(Run, position, headDigest)` facts. The only boundary is `PORT-LEDGER`: append receives current `ID-GEN`-qualified `ID-TXN`, expected prior position, canonical `LG-RECORD` digest, and previous digest; read returns verified ordered facts or typed failure. `ID-GEN` prevents stale controllers, while positions and record digest bind identity. Persist immutable records and witness heads; projections may observe only. No store, witness, adapter, or reader may decide lifecycle, mint authority, append directly, or acknowledge before `flush -> witness advance -> acknowledgement`.

## Observable success and terminal outcomes

Success is an exact candidate proving an append is flushed, witness-covered, and readable as the expected chain head; its durable output is one immutable record and witness head, not a lifecycle transition by itself. Valid readback is exactly: this proposal committed/adopt once; expected position absent/same identity retry; competing generation committed/fence proposer and recompute; same-generation different digest is integrity failure; read indeterminate enters Recovery. `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, and provider delivery are not produced here. Trust failure fences dispatch and stops autonomous Run advancement; it cannot claim a terminal `Stopped` record without a trustworthy witnessed append basis.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Validate every malformed/noncanonical identity, expected head, digest, chain link, schema, stale generation, duplicate position, or untrusted witness as `FC-INPUT`, `FC-SUBJECT`, `FC-FENCE`, or `FC-TRUST` at the boundary. `BND-WAIT-LEDGER` starts with each append/read and has the frozen 30s default/range 1s–5m; exhaustion halts dispatch and enters Recovery. A lost acknowledgement invokes the five-way readback only: confirmed absence and current generation retries identical bytes/identity; competing commit is adopted and old generation has no retry; same-generation mismatch, fork, broken chain, witness-ahead/contradiction, unavailable independent witness where rollback cannot be excluded, and indeterminate read are `FC-TRUST` or Recovery, never repair/retry. Restart verifies chain and witness before reconstruction; crash after flush/before witness is a verified floor that may advance, not rollback. Preserve all visible bytes/segments and witness evidence; no in-place rewrite, cleanup, compaction, or destructive recovery is authorized. Resume belongs to GF-011.

## Security and trust: validation, credentials, redaction, and authority widening

Length-limit framed records before allocation; canonicalize before digest; reject unknown schema/fields and all ambiguous input. The witness trust root must be independently configured (separate device, independent-trust path, or remote service); credentials are named configuration resolved in memory only, never record/log/evidence fields. Redact operational paths and credential values from errors. A ledger/witness fact proves currency only, never lifecycle or provider authority. The file adapter is unreachable from configuration and dispatch until exact manifest/build/environment evidence passes `CF-MECH-LEDGER`; a missing, stale, self-attested, or non-independent witness fails closed.

## Deliverables without delegated algorithm invention

Introduce `packages/ledger-contract/` (semantic types/validators), `packages/ledger-file/` (segmented reference adapter), `packages/witness-contract/`, `packages/testkit/ledger/`, and versioned `evidence/conformance/CF-MECH-LEDGER/` records; GF-001's final package layout may relocate these only without crossing units. Document the append/witness crash matrix in this story's evidence fixture metadata. **DR-6:** owner Arye Kogan; selected bounded option is D11's single-host append-only fsync-on-ack file reference plus independent witness; constraints are every `LG-*` clause, hash chain, five readback outcomes, witness-before-ack, and no rewrite; deferred segment/batch/layout algorithms cannot alter them. Evidence is exact adapter build/manifest/environment plus suite result; fallback is unreachable/stop, or a replacement only after the same suite; any different trust topology or contract requires `OWNER_DECISION_REQUIRED`.

## Test and evidence obligations

Run canonical record/identity unit vectors; conditional-head, stale-generation, duplicate, and malformed-frame contract tests; chain permutation and competing-controller tests; crash injection before append, after flush, after witness, and after lost ack; rollback/fork/witness-behind/ahead/mismatch/absence tests; restart/readback tests; hostile oversized/corrupt frame tests. `CF-MECH-LEDGER` oracle checks atomic expected-position behavior, flush-before-witness-before-ack, all five outcomes, independently trusted monotonic witness, and rollback restore detection. Record candidate content digest, source/fixture IDs, adapter build, manifest, environment, suite/probe versions, witness topology attestation, timestamps, and results. Provider/E2E tests are omitted because no provider or product effect is reachable.

## Exact acceptance

An independent reviewer (not the author/adapter provider) reviews one complete candidate: commit/content digest; bounded Run-ledger contract and reference build; exact `CF-MECH-LEDGER` evidence package and crash corpus metadata; witness binding/topology evidence; delivery metadata and `pnpm check`/CI outputs. Findings must be resolved; stale, partial, self-authored, or differently bound evidence rejects acceptance. Acceptance is a documentation/implementation-review verdict only, not landing; authoritative landing additionally requires the repository merge commit and required CI on that exact merged tree.

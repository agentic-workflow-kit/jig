# GF-003 — Runtime topology and semantic port contracts

## Outcome, value, and why now

Establish the fixed six-unit/eleven-port topology as compile-time contracts and dependency guards. This lets later stories implement facts and effects behind exactly one semantic crossing instead of accidentally creating a seventh authority path. It is earliest after the workspace and canonical boundary codec, and it enables the harness and pure kernel. It does not implement any provider, transport, storage, controller behavior, envelope builder, or port effect.

## Governing paths and stable IDs

[`runtime.md`](../../../redesign/design/runtime.md) is authoritative for the six units—`RT-OPERATOR`, `RT-CONTROLLER`, `RT-LEDGER`, `RT-EVIDENCE`, `RT-REGISTRY`, and `RT-WITNESS`—and the eleven ports: `PORT-CONSUMER`, `PORT-INTAKE`, `PORT-DECIDE`, `PORT-SESSION`, `PORT-WORKSPACE`, `PORT-VERIFY`, `PORT-DELIVERY`, `PORT-LEDGER`, `PORT-ARTIFACT`, `PORT-PUBLISH`, and `PORT-SOURCE`. It fixes passive stores, a single controller per Run, and ports as the only external crossings.

[D10](../../../redesign/design/decisions/D10-runtime-decomposition.md) fixes the modular single-authority runtime and delegates its private package layout through `DR-2`; [D13](../../../redesign/design/decisions/D13-envelope-production-boundary.md) fixes the Envelope Builder outside `SYS-JIG` and delegates typed semantic port realization through `DR-4`. `FC-AUTHORITY` is the topology's fail-closed result for an attempted authority or role crossing; this story supplies no other failure behavior.

The product-route mappings are explicit: `PC-README-2`, `PC-JIG-13`, and `PC-JIG-24` require the D2/D13 product, builder, and review-bypass boundaries; `PC-JIG-8` and `PC-CONCEPTS-3` require separated Runner/Worker/Reviewer/mechanism authority and credential limits; `PC-JIG-16` preserves D10 package deferral; `PC-JIG-17` preserves the private consumer and no Jig-side middleman; `PC-JIG-19` preserves operator-only start through the consumer/intake boundary; `PC-JIG-20` preserves the user-run/non-hosted deployment boundary; and `PC-CONCEPTS-9` preserves independent Track and per-Run controller boundaries. `STACK-1` requires provider-independent control/evidence/recovery, `STACK-2` identifies the four swappable seams, `STACK-3` keeps agent selection in a work profile, `STACK-4` requires attestation before configuration, `STACK-5` keeps credentials at the seam, `STACK-6` denies bundled-provider shortcuts, and `STACK-7` permits a custom provider only after its exact port proof. This topology supplies the common boundary, not a provider realization.

## Dependencies plus start evidence

GF-001 and GF-002 must each be merged, independently reviewed, and contained in the externally recorded execution base/tuple. Required evidence: the hermetic private graph/guard; exact codec version and all identity vectors; and a checked copy of runtime/D10/D13 with all six units and eleven ports enumerated. No unreviewed interface branch, fake transport, provider, or future package assertion satisfies a dependency. The build must prove no adapter is configured at start.

## In-scope and non-goals

In scope: private package/module boundaries; the six unit declarations; eleven semantic port interfaces; typed request/result envelopes that use GF-002 framing; dependency direction; explicit no-op/scripted fake implementations for tests; and static guards for forbidden imports/authority calls.

Out: controller reducer, event schemas, Operations, ledger commits, artifact pin behavior, providers/transports/encodings, user-facing SDK/CLI/MCP, envelope production, storage mechanisms, authentication implementation, and all public APIs. A port signature is not a selected provider protocol or algorithm.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`RT-OPERATOR` is the private facade and pre-controller intake host; it may propose commands and read projections only. `RT-CONTROLLER` is the future sole Authorize/Decide/Record/Reconcile unit. `RT-LEDGER`, `RT-EVIDENCE`, `RT-REGISTRY`, and `RT-WITNESS` are passive stores, with no lifecycle decision behavior. The Envelope Builder is outside `SYS-JIG`; `PORT-SOURCE` cannot reach the controller directly.

The eleven ports have declared direction and consumers: consumer delegates without bypass; intake handles immutable envelope acknowledgement; decide carries authenticated human decisions; session/workspace/verify/delivery reach mechanisms; ledger/artifact are storage crossings; publish is read-only; source serves the external builder. Inputs and outputs use versioned GF-002 frames and, where not yet defined, opaque typed placeholders that cannot be dispatched. Only the later named owner may turn a placeholder into a durable identity, schema record, event, or persisted fact. The structural fence rejects imports from stores to controller/core, port-to-port bypasses, `PORT-CONSUMER` direct control, provider imports of the kernel, and any write method outside the future controller/intake/registry record owners.

## Observable success and terminal outcomes

Success is a static package graph matching all six units and eleven ports, plus validated fake transports that cross the same boundary validation interface without changing authority. Reports name every allowed edge and each denied edge. This releases GF-004 and GF-005; it releases no deployable service.

The only terminal result is `topology accepted` or `boundary rejected`. No Run/Story exists, so `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, acceptance, landing, lifecycle transition, Operation, or provider result is impossible.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Unknown/missing port IDs, malformed GF-002 frames, illegal unit/port direction, attempted store decision, consumer bypass, builder/controller crossing, or a provider import fail build/test closed. `FC-AUTHORITY` is the only assigned typed topology failure; later owners define input, subject, and fence behavior. Fakes are pure/scripted, so no timeout, retry, effect identity, reconciliation, recovery, resume, or external cleanup applies. A failed compile is repaired by a new candidate; it is never silently retried as an effect.

## Security and trust: validation, credentials, redaction, and authority widening

Validate port IDs, direction, versioned frame boundaries, and declared capability surface at compile and contract-test time. There are no credentials or provider configurations. Test fixtures use synthetic principals and redact payload samples. No fake, environment setting, port implementation registration, or fallback can grant controller power or make an adapter reachable; real adapter registries do not exist in this story. Unqualified mechanisms are structurally unreachable because the contracts expose no selectable implementation.

## Deliverables without delegated algorithm invention

- Private topology declarations for the six named runtime units and eleven named port contracts, with direction and owner annotations.
- Compile/static dependency guards enforcing controller-only lifecycle authority, passive stores, private consumer delegation, read-only publish, and builder/source separation.
- GF-002-framed contract-test harness and validated scripted fakes that model no real effect.
- A machine-readable topology inventory and evidence report used by GF-004.

`DR-2`: Engineering realizes the private package graph by approved runtime/dependency seams, with D10's power allocation immutable; evidence is graph/static proof; fallback is the smallest graph retaining that allocation. `DR-4`: Engineering realizes typed in-process semantic ports, with transport deferred to mechanism edges; evidence is port contracts and fake validation; fallback is unavailable/unconfigurable provider access. Neither grants a transport, provider, or lifecycle algorithm.

## Test and evidence obligations

Required: package-graph/compile checks for all six units and eleven ports; positive contract tests through validated fakes; negative-authority tests for every forbidden edge; malformed/unknown-frame tests; and dependency permutation tests demonstrating no hidden import path. Replay/crash/timeout/reconciliation/recovery/provider/E2E tests are N/A: no durable control fact, clock, real adapter, or effect exists; the guard proves that absence. Capture topology manifest/version, graph digest, fake fixture version, denied-edge corpus, codec version, and exact candidate digest. `CF-BINDING` structural operands are prepared but no suite pass is asserted before GF-004.

## Exact acceptance

An independent reviewer compares the exact candidate topology against `runtime.md`, D10, and D13: six—not seven—units, eleven ports, builder outside the authority boundary, stores passive, controller exclusive, consumer/publish non-controlling, and no direct source-to-controller route. They require exact graph, contract, denied-edge, and fake-validation evidence. Any missing/extra crossing or configurable adapter fails closed. Acceptance of topology is separate from authoritative PR landing proof.

## DR choices

`DR-2`: question—how is the private runtime decomposed? Implementation owner—Engineering; bounded option—D10-aligned modular packages; immutable constraint—power ownership cannot move; deferred alternative—monolith; fallback—smallest valid topology. `DR-4`: question—how do boundaries cross? Implementation owner—Engineering + configuration; bounded option—typed semantic in-process ports, transport only behind the mechanism edge; constraints—D13's envelope boundary and no provider bypass; fallback—leave the port unavailable. Both proposed realization/configuration choices require exact external owner ratification/activation; Arye alone owns a change or widening. Any port that would require a new authority holder requires `OWNER_DECISION_REQUIRED`.

## PR boundary, relative size, and split

**M.** One coherent oracle: the fixed topology has no undeclared authority crossing. Expected paths are private module/package contracts, static guards, fakes, and topology fixtures. Excluded follow-up is all semantics and mechanisms. Do not split unit topology from port topology because their shared oracle is the authority graph; split only a separately failing external mechanism contract later, after this graph remains green and unconfigurable.

- All six units, eleven ports, D10/D13 boundaries, `DR-2`/`DR-4` owners, and no-adapter fence are enumerated.

- An independent reviewer can verify direction and power without history.

- Graph and contracts reject unknown/bypassing crossings; stores and builder cannot acquire lifecycle authority.
- Six-unit/eleven-port static and fake-transport evidence passes on the exact candidate.
- No real provider, credential, transport, or effect becomes configurable.
- Exact evidence, `git diff --check`, repository checks/CI, and independent exact-candidate review pass.

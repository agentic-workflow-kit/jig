# GF-062 — Supported local reference profile and closure

## Outcome, value, and why now

Admit exactly one supported local reference profile only when the immutable realization, provider,
and product conjunction is complete: all 39 conformance suites, all 44 fixed product-commitment
routes, all 56 imported guarantee IDs, and every selected realization/provider input. This is a
closure gate, not an implementation source or new behavior. It follows every other story and releases
only the documented supported-profile claim; it cannot waive, infer, substitute, or add semantics.

## Governing paths and stable IDs

`architecture-conformance.md` owns `CF-GATE-REALIZATION`, `CF-GATE-PROVIDER`, and
`CF-GATE-PRODUCT`; `product-readiness-gate-record.md` fixes the 44 route identities/settled route
composition and 56 imported commitments. The 39 suite names are the fixed inventory in delivery
verification. `DR-1/2/3/4/5/6/7/8/9/12` are consumed as already-recorded owner choices, not reopened;
the gate carries their manifest/evidence inputs and has no authority to choose a new option.

## Dependencies plus start evidence

All 45 listed predecessors must be merged on the selected current baseline with independent exact-
candidate review, required repository/CI evidence, and current manifest bindings. Start with immutable
route manifest (44 unique routes), import manifest (56 unique IDs), full 39-suite catalog/version,
realization build/tree/config digest, selected local host/profile/environment fingerprint, GF-060
Codex and GF-061 GitHub provider gate evidence, and every DR/provider qualification input. A missing,
stale, duplicate, altered, or substituted input means the profile is unsupported and gate does not run
as pass.

## In-scope and non-goals

In scope is deterministic collection, validation, conjunction evaluation, immutable closure evidence,
and supported-profile admission/withdrawal. Excluded are new product semantics, route minimization
or re-derivation, suite changes/waivers, implementation repair, provider fallback, broader platform
support, automatic owner decision, or a claim that a passing old candidate covers a new candidate.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The conformance harness from GF-004 reads evidence through existing private runtime/provider
boundaries and emits an exact Candidate Evidence Record (CER), route/import/suite manifests, and
gate verdict bound to build/tree/config/provider/host/freshness. It neither writes lifecycle facts
nor dispatches product effects. Durable evidence package is authoritative for this gate; source
ledger/artifact/provider facts remain authoritative for their domains. Only the approved gate
evaluator may calculate conjunction; owner still owns DR/product decisions, controllers own lifecycle,
and providers merely supply qualified evidence. The admission fence disables configuration of every
real provider/profile until all matching inputs pass.

## Observable success and terminal outcomes

Success is exactly one fully bound `CF-GATE-PRODUCT` pass where every one of 39 suite result,
44 route element set, 56 import mapping, realization input, and qualified provider input is present,
fresh, successful, and digest-matched. `CF-GATE-REALIZATION` and each `CF-GATE-PROVIDER` are
necessary inputs, not substitutes. Any false/missing/stale/ambiguous input yields fail-closed
unsupported profile with exact failing/missing identities; it does not infer `Landed`, acceptance,
or a product outcome. The gate's only terminal result is pass/fail for that exact profile/CER.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Malformed manifest/count/duplicate ID is `FC-VALIDATION`; unverifiable/digest-mismatched signature or
provenance is `FC-TRUST`; unavailable harness/storage/provider evidence is `FC-MECHANISM`; freshness
deadline is named applicable `BND-*`/`FC-BOUND`. Gate evaluation is effect-free: no same-effect retry
exists; rerun is a new exact observation after inputs are repaired/requalified. On interrupted
collection rebuild CER from immutable source evidence and reject partial output; fence stale
profile/config results. Cleanup may remove derived local caches but preserves CER/manifests/failures
and cannot re-enable a profile. Resume recomputes the whole conjunction against current exact input.

## Security and trust: validation, credentials, redaction, and authority widening

Validate canonical manifests, uniqueness/counts, signature/digest/freshness, current selected
baseline, host/profile configuration, credential-class attestations, and no secret fields. Harness
resolves named test/provider credentials only in memory; CER/log/export carries redacted identifiers,
digests, and safe environment fingerprint, never tokens/paths/prompts. No individual suite, provider,
route, fallback, or local profile flag can widen authority or make a real provider reachable before
the pure conjunction passes.

## Deliverables without delegated algorithm invention

Deliver immutable manifest schemas/validator, pure conjunction evaluator, CER bundle format,
profile admission fence, reproducible local runner, route/import/suite completeness checks, failure
report, and exact evidence recorder. The applicable DR records remain selected by Arye in predecessor
stories: their constraints/evidence/fallbacks are input checks; a missing choice is
`OWNER_DECISION_REQUIRED`, not a default. No algorithm may reinterpret routes, imports, suite
outcomes, provider qualification, or product meaning.

## Test and evidence obligations

Test 39-suite manifest exactness, 44-route and 56-import uniqueness/count/completeness, each missing/
duplicate/stale/substituted/digest-mismatch failure, profile/provider/realization mutation invalidation,
fresh CER rebuild, signature/redaction/secret absence, cache/crash/resume, and full supported local
profile smoke through land/reject/block/park/suspend/stop/resume/swap/export/cleanup and stated crash
boundaries. Require all 39 named suite outputs, `CF-GATE-REALIZATION`, individual provider
`CF-GATE-PROVIDER`, and `CF-GATE-PRODUCT`, with exact build/tree/manifest/config/host/provider/output
digests. There is no omitted provider/E2E category: all admitted selected inputs are required.

## Exact acceptance

Independent reviewer receives the complete exact CER: content/target/build/tree/config/profile/host
digests; 39 suite results; ordered 44 routes; ordered 56 imports; DR/provider manifests; raw redacted
evidence references; and freshness timestamps. They independently recompute the conjunction and
require no missing/failing/stale/substituted element. Review verdict attaches only to that CER;
authoritative landing is a separate merged commit/CI proof and any byte/input change requires a new
CER and review.

## DR choices

All ten carried DR records have prior owner Arye selections. This story records for each: selected
option/constraint/evidence/fallback from its owning story is a required immutable input; alternatives
are not reconsidered; missing/changed choice disables the profile and requires owner decision. The
gate has no independent DR and no permission to synthesize a default.

## PR boundary, relative size, and split

L, one pure final-conjunction oracle. Expected harness/manifest/profile/evidence/test paths; exclude
new runtime/provider semantics. Do not split the final evaluator: partial passes have no supported-
profile meaning. Independently failing provider qualification remains in GF-060/GF-061.

## Definition of Ready

- Every predecessor, DR selection, selected provider, host/profile, and exact CER input is merged/current/independently evidenced.
- Immutable 39-suite, 44-route, 56-import inventories, conjunction rule, redaction, and fail-closed admission fence are reviewable.

## Definition of Done

- The evaluator is pure, complete, exact-subject-bound, and cannot pass or configure a profile on partial/stale/substituted evidence.
- Full mutation, crash/rebuild, secret, provider, real-profile smoke, and all-gate evidence passes on one CER.
- Independent exact-CER review, `git diff --check`, repository checks, CI, and separate authoritative landing proof pass.

# GF-013 — Immutable artifact storage and protected routing

## Outcome, value, and why now

Deliver immutable artifact storage with deterministic holder-class routing: five pre-Run configuration/intake classes are protected, and six controller-mediated evidence classes are disposable only through an exact two-pin, independently witnessed lookup. It enables later evidence binding while ensuring retention/disposal cannot counterfeit authority. Acceptance, evidence sufficiency, exports, intake behavior, provider qualification, and direct storage access remain unavailable.

## Governing paths and stable IDs

`guarantees.md` maps this to `SEC-1` (safe-to-retain trail) and `STACK-5` (credentials/irreversible authority remain governed). `evidence-handling.md` owns classes/routing/immutable evidence; `runtime.md` owns `RT-EVIDENCE`, `PORT-ARTIFACT`, modes and `EV-ARTIFACT-FACT`; persistence owns the disposable pin witness sequence; control-plane assigns `CP-EVIDENCE` request and `CP-TRANSITION` acknowledgement; data/identity owns holder binding and no secret fields. `OPC-ART-PUT` alone puts/verifies bytes plus the exact temporary-event/intended-holder two-entry set; `OPC-ART-GET` is read-only; `OPC-ART-DISPOSE` is only `release-pin` (no bytes) or guarded owner-authorized `dispose-bytes`.

## Dependencies plus start evidence

Require merged GF-002 canonical artifact identity/digest codec, GF-005 operation intent/authority kernel, and GF-010 exact ledger/witness pass. Verify the current baseline, approved artifact-provider manifest/resource scope, deterministic holder-class matrix, both non-aliasing contexts, and independent disposable-pin witness line. A holder scan, path label, same-object copy, or unreviewed adapter cannot prove start safety.

## In-scope and non-goals

In scope: immutable put/get, routing guard, protected continuity, disposable reverse-reference pin lookup, two-pin registration, release receipt, guarded deletion preconditions, and ledger-owned witness acknowledgement. Exclude evidence manifest semantics (GF-014), acceptance/export/retention policy, intake orchestration, provider approval, cleanup lifecycle, and direct consumer/provider storage access.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`RT-EVIDENCE` is passive and exposes only `PORT-ARTIFACT` through `CP-MEDIATOR`; `CP-EVIDENCE` requests operations, `CP-TRANSITION` adopts/retires facts and advances `LG-WITNESS` via `PORT-LEDGER`, while `RT-WITNESS` holds the one deployment-scoped disposable-index head. Inputs bind approved `ID-MANIFEST`/resource scope, holder class, exact artifact digest/subject, operation/fence, temporary event and intended durable-holder tuples. Persist immutable object bytes/digest, immutable protected continuity, disposable hash-chained lookup mutations, returned `(position, headDigest)`, and witness line. The store can never directly move/dispose/alias protected addresses, write witness, adopt facts, or decide lifecycle; `CP-EVIDENCE` cannot direct-mutate, and a witness gives no authority.

## Observable success and terminal outcomes

Success is immutable digest-verified retrieval and, for disposable material, an `EV-ARTIFACT-FACT` proving a flushed exact two-pin mutation followed by matching witness advance before acknowledgement. Adoption changes no lookup; rejection retires both tuples before release. Protected disposal/move/alias is rejected. This story cannot accept/reject a Candidate, land, release dependencies, or autonomously dispose bytes. An uncertain mutation retains/preserves pins; trust failure stops rather than silently deletes.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Malformed/oversize/noncanonical subject/digest/context is `FC-INPUT`/`FC-SUBJECT`; stale operation/fence is `FC-FENCE`; missing content, pin tuple, mode/owner authorization, or prohibited protected operation fails closed as `FC-EVIDENCE`/`FC-AUTHORITY`; changed resource binding, fork/rollback/behind/mismatched/missing witness or unverified continuity is `FC-TRUST`. `BND-WAIT-MECHANISM` bounds mediated requests and `BND-RETRY` limits attempts; `BND-WAIT-LEDGER` covers witness commit and exhaustion enters Recovery. Before effect, intent is GF-005/015-recorded; an uncertain put/release is reconciled by stable `ID-OP`, exact lookup head and witness, never retried blindly. Confirmed absence plus recorded reauthorization may retry same effect; otherwise preserve pins and park/escalate. On restart `CP-RECOVERY` verifies class-to-context binding and lookup chain/head against witness before adoption, release, or dispose. Cleanup is only future lifecycle-authorized release/guarded delete; preserve protected objects and uncertain disposable references.

## Security and trust: validation, credentials, redaction, and authority widening

Bound byte size/type/digest and canonical metadata before storage; immutable content addressing never permits overwrite. Credentials are manifest-declared names resolved only in memory; objects/evidence/logs never contain secrets, and errors redact locators/credentials. Trust roots are approved exact artifact manifest/resource binding and an independent witness that does not share RT-EVIDENCE/pin lookup/backups. Both routes are fixed by existing holder class, never user/provider choice; protected/disposable copies of equal bytes are separate objects. Unqualified adapter/configuration path is unreachable until exact `CF-MECH-ARTIFACT` and ledger witness evidence passes.

## Deliverables without delegated algorithm invention

Add `packages/artifact-contract/`, `packages/artifact-file/`, `packages/artifact-routing/`, `packages/testkit/artifact/`, and `evidence/conformance/{CF-MECH-ARTIFACT,CF-MECH-LEDGER}/` operands. **DR-6:** Arye owns the selected physical-storage bounds: five/six class routing, non-alias protected context, exact two-pin mutable lookup, flush->ledger witness->ack, and restore currency are immutable; engineering can choose bytes/layout/index technique only within them. Evidence is exact adapter build/manifest/environment and crash suite; fallback is protected preservation/adapter unreachable or trust stop. A changed class, context scope, disposal mode, or witness route requires owner decision.

## Test and evidence obligations

Test each eleven holder class route; protected move/dispose/alias rejection; immutable put/get digest/read vectors; exact and partial/digest-only two-pin rejection; adoption/rejection retirement ordering; release-pin no-delete and guarded delete authorization; flush/witness/ack crash points; lost ack/confirmed absence/uncertain mutation; restore behind/fork/mismatch/missing witness; stale fence/context/manifest; hostile oversized/secret-like input. `CF-MECH-ARTIFACT` oracle checks all port/mode guards and two-pin rules; joint `CF-MECH-LEDGER` checks witness ordering/currency. Record exact artifact/object/holder/lookup/witness identities, build/manifest/environment, fixture and probe versions, fault point, redacted result. Acceptance/E2E are omitted: no acceptance/delivery path exists.

## Exact acceptance

Independent reviewer receives one candidate digest, class routing table, immutable and pin contracts, exact artifact/ledger suite evidence, witness/manifest bindings, redaction scan, and CI/check metadata. Incomplete holder coverage, self-attestation, stale/different context/witness evidence, or unresolved findings fails closed. Candidate approval is not storage deployment or landing; authoritative landing is a separate merged-tree CI proof.

## DR choices

Only DR-6 applies, with selection/owner/constraints/evidence/fallback stated above. Algorithms may not infer a pin set from visible holders; no other authority/policy choice is delegated.

## PR boundary, relative size, and split

**L.** The semantic oracle is non-aliasing protected routing plus witnessed disposable two-pin currency. Paths are artifact contract/router/reference adapter/testkit/evidence. `GF-013a` may deliver fixed routing/protected guards and a fake disposable contract; `GF-013b` realizes disposable lookup only while the adapter remains unconfigurable. Evidence admission and cleanup stay out.

## Definition of Ready

- GF-002/GF-005/GF-010 exact merged evidence, artifact manifest/resource binding, two contexts, and independent witness line are current.
- Holder classes, operation modes, ports, writers, facts, bounds/failures/recovery, and suite oracles are explicit.
- DR-6 and split/fallback are recorded; no artifact adapter is configured.

## Definition of Done

- Protected no-move/no-dispose/no-alias and disposable exact-two-pin flush-witness-ack rules are implemented and independently evidenced.
- All uncertainty reconciles or preserves; no lookup is inferred, no direct mutation/witness write is possible, and recovery verifies currency before action.
- Exact suites, secret/redaction negative tests, `pnpm check`, `git diff --check`, CI, and independent review pass.

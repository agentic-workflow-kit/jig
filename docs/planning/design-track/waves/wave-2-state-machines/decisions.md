## Safe assumptions confirmed

The frame's two `safe assumption` items and its one `provided` sequencing fact were confirmed by
the coordinator and carry into the three story briefs unchanged:

- **s1 → s2 sequencing** (safe assumption, confirmed): `w2-s1-work-item-lifecycle` has
  `depends_on: []`; `w2-s2-run-lifecycle-and-recovery` has `depends_on:
[w2-s1-work-item-lifecycle]`. The run's `stopped` / `resumed` / recovery semantics are defined
  partly in terms of work-item state (an unattended `parked` work item drives `run.stopped`;
  `orchestration.md` prose and M5a FAIL-004), so s2 needs s1's guard vocabulary in hand.
- **Guard ownership** (safe assumption, confirmed): `w2-s1`'s work-item transition table treats
  `authorize(request, boundPolicy) → grant \| deny \| route` as an **external guard predicate it
  consumes and cites** from `authorization.md`; `w2-s1` owns only which state transition each
  outcome triggers (grant → proceed toward `done`; deny → `blocked`; route → `parked`), while
  `authorization.md` keeps owning the classifier's internal shape (the CFG-10 category boundary,
  escalation routing). This is the same "deepen a stub via citation, not overwrite" discipline
  D-001 rests on.
- **s3 consolidation dependency** (provided, stated directly in the brief):
  `w2-s3-invariant-catalog` has `depends_on: [w2-s1-work-item-lifecycle,
w2-s2-run-lifecycle-and-recovery]`; it is a post-hoc consolidation checkpoint, not a third
  independent lifecycle area.

# GF-024 — Witnessed idempotent intake and Run birth

## Outcome, value, and why now

Create the single witnessed intake commit point: an approved envelope returns one immutable
accepted/rejected acknowledgement, and only an accepted acknowledgement may derive `ID-RUN` and
trigger idempotent ledger/controller creation. Accepted successor intake atomically commits its ack
and cut claim; rejection proves no Run. This closes Phase 2 without authorizing any dispatch.

## Governing paths and stable IDs

`runtime.md` assigns `CP-INTAKE` to short-lived `RT-OPERATOR` and `PORT-INTAKE`; persistence owns
`LG-INTAKE`, witness-before-return, atomic successor pair, recovery, and the stable ack tuple.
`data-and-identity.md` owns `SCH-ENVELOPE`, `SCH-INTAKE-ACK`, `SCH-INTAKE-CUT-CLAIM`, and post-
position `ID-RUN`; D16 locks pair/digest/recovery closure. `envelope-production.md` owns submit
identity and independent intake validation. `DR-4`/`DR-6` cannot weaken port or storage semantics.
`CF-ENVELOPE`, `CF-MECH-LEDGER`, and successor crash/second-winner corpus are oracles.

## Dependencies plus start evidence

Require merged GF-010 witnessed ledger/conditional-create/readback evidence, GF-011 recovery/
fencing evidence, GF-013 protected context evidence, GF-020 exact qualified source evidence, and
GF-023 exact owner proposal/manifest approval evidence. Reconfirm current manifests/proofs,
envelope/bound input, exact storage+witness realization, and selected baseline. A submitted
proposal, builder success, created projection, or unwitnessed ack is never start evidence.

## In-scope and non-goals

In scope: independent envelope/preflight validation, acknowledged acceptance/rejection, staged
digest domains, composition-key idempotency, `LG-INTAKE` create/readback/witness, post-ack Run
ledger/controller reconstruction, and successor pair competition. Exclude Run lifecycle decisions,
scheduler/effects, re-planning semantics, provider proof production, approval UX, projections as
authority, and any dispatch before subsequent stories.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`EP-SUBMIT` sends canonical `SCH-ENVELOPE` via `PORT-INTAKE`; `CP-INTAKE` in `RT-OPERATOR` is sole
caller of `PORT-LEDGER` for pre-Run `LG-INTAKE`. It independently validates plan/policy/profile,
approval, manifest/proof/config-read handles, bounds, and successor lineage. It stages
`acknowledgementContentDigest` before position; after durable conditional create/readback and
`LG-WITNESS`, stable tuple is `(compositionDigest, intakeCreatePosition, acknowledgementContentDigest)`.
Only an accepted tuple derives `ID-RUN`. For a successor, it atomically creates ack plus full-cut-
keyed `SCH-INTAKE-CUT-CLAIM` at one position; both commit or neither. Stores witness/return facts;
they do not decide. Builder submits/observes; no provider, preview, or preflight record may create
an ack, Run, transition, grant, or dispatch.

## Observable success and terminal outcomes

Success is a witness-verified immutable terminal ack bound to exact composition/proposal/approval,
attempt handles/digests/consumption, disposition, and—if accepted—frozen envelope plus genesis basis.
Accepted ack releases only idempotent ledger creation/controller spawn; it does not dispatch.
Rejected ack is terminal `NotRun`, derives no `ID-RUN`, ledger, controller, index, or projection
beyond itself. Same digest returns byte-equivalent ack. Same-cut different digest returns a durable
rejected ack naming witnessed winner binding and never fences predecessor resume. No uncertain or
partial pair can become accepted.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Input/preflight mismatch is `FC-INPUT`/`FC-SUBJECT`/`FC-EVIDENCE`; unauthorized action is
`FC-AUTHORITY`; ledger/witness/pair corruption, wrong winner, fork, or unverifiable head is
`FC-TRUST`. `BND-WAIT-LEDGER` is 1s–5m (default 30s); exhaustion enters Recovery, never a
Story-blocked workaround. Preflight attempts retain their own `BND-WAIT-MECHANISM`/`BND-RETRY`
chain and are not reset. Lost intake response reads the same composition key and returns exactly
the existing bytes. Complete pair/witness behind may advance witness before adoption; witness-ahead,
missing companion, mismatch, or fork is never repaired one side at a time. No terminal ack means
no Run and only validated attempt-chain resume; accepted ack with absent/incomplete ledger rebuilds
from frozen ack; rejected ack rebuilds neither. Index without ack is discarded/rebuilt. There is no
effect to retry or cleanup before later lifecycle stories.

## Security and trust: validation, credentials, redaction, and authority widening

Validate canonical/versioned envelope, digest domains, owner/manifest/proof/freshness/scope,
configuration attempt chains, composition and successor cut key; reject unknown, stale, ambiguous,
cross-boundary, duplicate-conflict, noncanonical, or oversize values. Credentials are never carried;
only previously admitted provider identities/approved names are referenced. Redact source/config/
proof payloads while retaining immutable required digests and handles. `LG-WITNESS` must be
independent of intake/index/backups and flush must precede witness which precedes return. A provider,
preview, approval, preflight attempt, projection, or fallback cannot widen intake authority; no
unqualified adapter can reach submission validation.

## Deliverables without delegated algorithm invention

Deliver intake validator, canonical staged ack/claim digest builders, `LG-INTAKE` semantic
conditional-create/readback interface, independent witness integration, recovery/rebuild logic,
second-winner handling, and crash/evidence corpus. `DR-4` permits a typed intake/ledger transport
only beneath fixed sole-caller/atomicity semantics; evidence is intake/ledger conformance and
fallback is fail-closed. `DR-6` permits physical storage only if it preserves one shared position,
atomic pair, independent witness, protected context, and readback; evidence is `CF-MECH-LEDGER`;
fallback is no intake. No digest domain, authority, or recovery protocol is delegated.

## Test and evidence obligations

Test accepted/rejected genesis; exact same-digest byte-equivalent replay; different digest; all
independent preflight failures; no-Run rejection; staged digest exclusions/derivation; witness
flush-before-return; ledger deadline/recovery; crashes before create, after create/before witness,
after witness/lost response, and post-ack ledger/controller rebuild; index-without-ack discard;
successor atomic pair/position/head; same-cut second winner/rejected binding; partial pair,
witness-ahead/behind, fork/mismatch corruption; and negative authority/dispatch. Record exact
envelope, approvals, attempts, ack/claim bytes/digests, positions/head/witness, build/storage/
suite/probe/corpus/candidate metadata for `CF-ENVELOPE` and `CF-MECH-LEDGER`. E2E ends at Run birth;
lifecycle/effect/landing tests are excluded.

## Exact acceptance

An independent reviewer receives exact candidate/baseline/target digest, frozen envelope/approval/
manifest/proof/attempt handles, ack/claim digest domains and bytes, ledger+witness basis, full crash
and second-winner corpus results, suite/build/delivery metadata, and findings. They require exact
candidate deterministic evidence and no unresolved finding. Acceptance is separate from
authoritative landing: merged commit/CI proof is required, and a partial/self/stale/differently
bound verdict fails closed.

## DR choices

- `DR-4` — Engineering/configuration; typed intake/ledger transport selected only under fixed
  `CP-INTAKE` sole-caller, atomic pair, and witness-before-return constraints; conformance evidence;
  fail closed on unavailable transport.
- `DR-6` — Engineering; physical conditional-create/witness realization only; immutable pair,
  digest, protected-context, independent-trust rules; `CF-MECH-LEDGER`; no supported storage means
  no intake. No other choice is delegated.

## PR boundary, relative size, and split

`L`, one intake authority oracle. Expected paths are intake/ack/claim/witness/recovery tests and
evidence. Split `GF-024a` genesis acknowledgement/recovery from `GF-024b` successor pair only if
`a` stays green and successor submission is structurally disabled; do not split ack from its witness
or include lifecycle/effect code.

## Definition of Ready

- All five dependencies are merged with current exact source, approval, storage, recovery, and
  protected-context evidence.
- IDs, ports, sole authority, durable facts/digest domains, bounds, failures, recovery, and oracles are named.
- `DR-4`/`DR-6` are bounded; no provider/preview/preflight path can mint intake or runtime authority.
- Independent review can execute the crash/second-winner start package without conversation history.

## Definition of Done

- Rejected ack demonstrably creates no Run; accepted ack is witnessed before return and alone
  derives Run birth/rebuild basis.
- Same-digest/lost-response results are byte-equivalent; successor ack+claim is one atomic,
  witnessed commit and invalid pair recovery fails closed.
- Required schema, authority, replay, concurrency, timeout, crash, recovery, provider-gate, and
  `CF-*` evidence pass; no dispatch exists.
- Exact evidence, `git diff --check`, repository checks/CI, and independent review pass.

# GF-005 — Pure authority kernel and catalog reducer

## Outcome, value, and why now

Deliver the closed, pure decision kernel that realizes the catalog, not an effectful controller: all 17 Story states, Run phases, 32 event discriminants, 29 Operation discriminants, and total `SCH-EVENT`/`SCH-TRANSITION`/`SCH-OPERATION` validation. Its outcome is a replayable decision that either rejects an illegal trigger or returns an immutable next-state transition plus ordered Operation intents; the caller must record it before adoption or dispatch. This is the first safe executable semantic core because GF-002 supplies exact identity/binding, GF-003 fences authority seams, and GF-004 prevents an unbound conformance claim. It enables later durable ledger and recovery stories, but makes no port effect, provider, storage, or Run creation available.

## In-scope and non-goals

In scope: immutable catalog types; exhaustive discriminated unions; pure state selectors; transition legality/containment validation; deterministic ordering by committed trigger/ledger order; pure failure classification; immutable transition and Operation-intent construction; and replay/illegal-edge fixtures.

Out: ledger append/witness, controller process/generation acquisition, intake, scheduler, artifact access, mechanism dispatch, provider/result parsing, clocks/timers, policy defaults, recovery/reconciliation algorithm, projections, user commands, finalization, and landing. The kernel must not choose algorithms delegated to later stories merely by making an implicit default.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The kernel is the pure core of future `RT-CONTROLLER`/`CP-TRANSITION`; it has no port and no mutable store. Inputs are an authoritative-state snapshot supplied by a future verified ledger reader, exactly one validated `SCH-EVENT`, current immutable catalog/version, identity/binding/fence facts, and explicit bound/failure facts. Output is either a typed rejection or a proposed immutable `SCH-TRANSITION` with zero or more `SCH-OPERATION` intents, exact input/output bindings, and no side effect.

Only the future `CP-TRANSITION` may adopt output after a conditional ledger record. `CP-SCHEDULER`, `CP-FINALIZER`, `CP-EVIDENCE`, `CP-ESCALATION`, and a port boundary can propose a trigger but cannot mutate state through the kernel directly. `ID-EVENT`, `ID-TXN`, and `ID-OP` are represented/bound using GF-002 but are not minted as durable facts until a later committed transition. The fence is capability/API shape: pure output lacks a port handle, adapter, write method, or dispatch operation; a caller must provide confirmed record evidence before any adoption/dispatch layer can consume an intent.

## Observable success and terminal outcomes

Success is a total, deterministic decision for every legal catalog state/event pair and an explicit typed rejection for every illegal, incomplete, wrong-subject, wrong-fence, or out-of-order pair. The same authoritative input sequence yields bit-identical decision output and ordered intents. It releases GF-010's durable core implementation dependency and the first executable evidence for `CF-DETERMINISM`, `CF-BINDING`, and structural `CF-ORDERING` operands.

The kernel can propose cataloged lifecycle outcomes only as an uncommitted plan; it cannot itself make a Story `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, `Landed`, or accepted. It cannot start a Run, dispatch an Operation, or accept/land a candidate. An unknown state/event/Operation is terminally rejected by the kernel, not mapped to a default behavior.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

The reducer returns the cataloged failure classification and prescribed non-effect disposition for invalid inputs: malformed trigger is `FC-INPUT`, unauthorized power is `FC-AUTHORITY`, wrong basis is `FC-SUBJECT`, stale generation is `FC-FENCE`, and unknown/untrusted state is fail-closed. It preserves the distinction among `FC-MECHANISM`, `FC-EFFECT`, `FC-BOUND`, and `FC-TRUST` for their future owners. Bound start/deadline/exhaustion facts are inputs, never timers derived by this story.

The kernel performs no retry. It represents that an effectful same `ID-OP` may only be re-dispatched after a later confirmed-absent fact and recorded reauthorization; all uncertain/indeterminate effect paths remain non-dispatchable and eventually park through later reconciliation. There is no external effect to reconcile, no persisted state to recover, and no resource to clean. Replay/resume recomputes from the exact prior authoritative facts; any disagreement is a test failure, not a silent repair.

## Security and trust: validation, credentials, redaction, and authority widening

Validate union discriminants, schema/catalog version, identity hierarchy, subject/basis binding, active fence, lifecycle position, operation class, and exact event ordering before calculating a decision. Reject unknown fields/discriminants and avoid logging arbitrary payloads; tests use bounded synthetic values. The pure core accepts no credentials. A provider fact, evidence artifact, fallback, or fake cannot mint authority because it first requires validated boundary ownership and then a later durable record. No adapter is linked or configurable, so an unqualified adapter is unreachable by construction.

- Pure total reducer/selectors for `SCH-EVENT`, `SCH-TRANSITION`, and `SCH-OPERATION`, including exact identity/fence/basis bindings and record-before-adopt/dispatch intent barrier.
- Typed failure/outcome model preserving the 12 literal failure classes and bound references without selecting values or providers.
- Illegal-edge, wrong-subject/fence, catalog-exhaustiveness, determinism, replay, and permutation fixture corpus wired to GF-004.

`DR-3`: Engineering selects an immutable pure reducer/selectors with explicit tables. Constraints are catalog closure, I4 ordering, I5 record-before-adopt/dispatch, and no hidden I/O. Evidence is exhaustive/replay/permutation proof. Fallback for an unimplemented transition is typed rejection; it is never inferred. The choice does not settle scheduling, policy, storage, recovery, or provider algorithms.

## Test and evidence obligations

Required: deterministic unit/schema tests for all catalog entries; compile/exhaustiveness tests that fail on a new/unhandled discriminant; contract tests for every legal edge and illegal-edge corpus; negative-authority and hostile-input tests; replay/permutation tests on equivalent committed event sequences; and fault tests proving no output exposes dispatch before record confirmation. Crash, timeout, reconciliation, provider, and E2E tests are N/A to the pure kernel—there is no process, clock, durable ledger, adapter, or effect—and are justified by dependency guards; later GF-010/GF-011/GF-015 own them. Record candidate/catalog/reducer digests, exact input fixture identities, ordered event sequence, oracle output, deterministic seed, and harness version. Execute and record the applicable `CF-DETERMINISM`, `CF-BINDING`, and structural `CF-ORDERING` operands through GF-004; do not claim full gates yet.

## Exact acceptance

An independent reviewer receives the exact candidate package: content/baseline digest, catalog trace matrix (17 states, Run phases, 32 events, 29 Operations), implementation/harness versions, full legal/illegal edge evidence, replay/permutation records, no-I/O/static-guard report, and unresolved findings state. They verify totality, no false default, ownership only at `CP-TRANSITION`, and record-before-adopt/dispatch. A partial catalog, self-authored/stale evidence, or a reducer that can call a port fails closed. Reviewer acceptance is only a kernel acceptance; authoritative landing requires separate PR/CI proof.

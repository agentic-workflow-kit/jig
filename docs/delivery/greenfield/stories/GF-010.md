# GF-010 — Witnessed conditional Run ledger

## Outcome, value, and why now

Deliver the complete storage-agnostic semantic `PORT-LEDGER` contract: conditional Run append/readback, `LG-INTAKE` atomic acknowledgement-plus-successor-cut pair, `LG-PREFLIGHT-ATTEMPT`, `LG-WITNESS`, and scripted/fault fixtures for five-way readback. It gives later controller recovery, registry, artifacts, and mediation a trustworthy base. Any segmented-file realization, concrete ledger/registry/witness provider, or provider configuration remains exclusively GF-025's work after its exact gate; artifact routing is GF-013 and all product effects remain impossible.

## Governing paths and stable IDs

`persistence-and-projections.md` and D11 own the mapped semantic contract; `mechanism-and-provider-contracts.md` owns `CB-STORE`. `RT-LEDGER` is passive authority storage, `RT-WITNESS` independently records currency, and `PORT-LEDGER` is the sole semantic boundary. In this semantic story, `CB-STORE` binds one scripted, unapproved fixture request to exactly one intake composition-digest key or one Run's generation-qualified positions and corresponding witness head. `CP-INTAKE` or `CP-TRANSITION` authorizes the scoped request and `CP-MEDIATOR` validates its subject, expected head, resource scope, and fixture binding before dispatch. The binding cannot reach another intake key, Run, registry line, witness head, or any artifact resource; it cannot be rebound after dispatch or used as provider qualification. `LG-RECORD` binds `ID-TXN`; `LG-POSITION` orders it; `LG-APPEND` conditionally commits; `LG-ACK` returns only after durable witness coverage; `LG-READ` and `LG-CHAIN` verify history; `LG-INTAKE` owns acknowledgement/cut-pair atomicity; `LG-PREFLIGHT-ATTEMPT` is the non-authoritative pre-Run primitive; `LG-SNAPSHOT` is a disposable verified accelerator; and `LG-WITNESS` detects rollback. `ID-EVENT` is minted only after validation/commit. `FC-TRUST`, `BND-WAIT-LEDGER`, `CF-ORDERING`, `CF-TRUST-STOP`, `CF-MECH-LEDGER`, and `ledger_acknowledgement` respectively bound stop, wait, ordering, trust-stop, scripted semantic-contract, and acknowledgement evidence. The D11 segmented append-only file reference realization is deferred to GF-025; DR-6 cannot choose it here.

## Dependencies plus start evidence

Start only when GF-002's merged codec/vector evidence proves canonical identity/digest framing and GF-005's merged pure transition kernel proves the sole Run writer, `ID-TXN`, and record-before-adopt/dispatch intent shape. Record the exact external activation and separately bind approved package `P = Q + durable R identifier + PASS`, any authoritative landing-equivalence record for `P`/`Q`, and the observed execution-base ref/commit/tree with predecessor containment. Verify an explicit scripted witness fixture binding, marked unapproved and unreachable from configuration/dispatch, models a separately trusted store rather than ledger storage or backups. GF-025's qualified witness/provider binding is a later gate and is not start evidence for this semantic story. A branch assertion, a same-host adjacent file, or an unqualified alternate backend is insufficient.

## In-scope and non-goals

In scope: semantic Run chain, generation-qualified append/readback, `LG-INTAKE` pair and preflight primitives, snapshots as verified accelerators, and scripted witness/readback faults. Exclude concrete files, directories, batching, real-provider configuration/qualification, artifact routing, public APIs, and effects. This semantic half stays useful and green while selected ledger/registry/witness providers stay unreachable until GF-025.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`RT-CONTROLLER`/`CP-TRANSITION` is sole Run-record writer; `CP-INTAKE` owns only the pre-Run intake subject, `CP-MEDIATOR` validates every `CB-STORE`, `RT-LEDGER` is passive storage, and `RT-WITNESS` stores monotonic `(Run, position, headDigest)` facts. The only boundary is `PORT-LEDGER`: append receives current `ID-GEN`-qualified `ID-TXN`, expected prior position, canonical `LG-RECORD` digest, and previous digest; read returns verified ordered facts or typed failure. `ID-GEN` prevents stale controllers, while positions and record digest bind identity. Persist immutable records and witness heads; projections may observe only. No store, witness, adapter, or reader may decide lifecycle, mint authority, append directly, cross-bind a subject/resource, or acknowledge before `flush -> witness advance -> acknowledgement`.

## Observable success and terminal outcomes

Success is an exact candidate proving an append is flushed, witness-covered, and readable as the expected chain head; its durable output is one immutable record and witness head, not a lifecycle transition by itself. Valid readback is exactly: this proposal committed/adopt once; expected position absent/same identity retry; competing generation committed/fence proposer and recompute; same-generation different digest is integrity failure; read indeterminate enters Recovery. `Blocked`, `Parked`, `Rejected`, `NotRun`, `Stopped`, and provider delivery are not produced here. Trust failure fences dispatch and stops autonomous Run advancement; it cannot claim a terminal `Stopped` record without a trustworthy witnessed append basis.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Validate every malformed/noncanonical identity, expected head, digest, chain link, schema, stale generation, duplicate position, or untrusted witness as `FC-INPUT`, `FC-SUBJECT`, `FC-FENCE`, or `FC-TRUST` at the boundary. `BND-WAIT-LEDGER` starts with each append/read and has the frozen 30s default/range 1s–5m; exhaustion halts dispatch and enters Recovery. A lost acknowledgement invokes the five-way readback only: confirmed absence and current generation retries identical bytes/identity; competing commit is adopted and old generation has no retry; same-generation mismatch, fork, broken chain, witness-ahead/contradiction, unavailable independent witness where rollback cannot be excluded, and indeterminate read are `FC-TRUST` or Recovery, never repair/retry. Restart verifies chain and witness before reconstruction; crash after flush/before witness is a verified floor that may advance, not rollback. Preserve all visible bytes/segments and witness evidence; no in-place rewrite, cleanup, compaction, or destructive recovery is authorized. Resume belongs to GF-011.

## Security and trust: validation, credentials, redaction, and authority widening

Length-limit framed records before allocation; canonicalize before digest; reject unknown schema/fields and all ambiguous input. The scripted witness fixture must model independent trust through a separately controlled logical store and fault surface, but it is not an independently configured trust root and cannot attest a separate device, independent deployment path, or remote service. Real trust-root configuration and qualification belong only to GF-025. The fixture uses no credentials or configurable provider path; record/log/evidence fields never contain secret values, and errors redact operational paths. A ledger/witness fact proves currency only, never lifecycle or provider authority. Selected providers are unreachable from configuration and dispatch until GF-025 records their exact provider gate; `CF-MECH-LEDGER` here only exercises the semantic contract with scripted fixtures. Missing, stale, self-attested, or non-independent fixture proof fails closed without claiming real-provider independence.

## Deliverables without delegated algorithm invention

Deliver semantic ledger validators, scripted ports/fault fixtures, contract documentation, and exact `CF-MECH-LEDGER` fixture evidence at the responsibility seams; GF-001 decides package names and counts. **DR-6:** owner Engineering; selected bounded option is the D11 contract including chain, five outcomes, pair atomicity, witness-before-ack, and no rewrite. Evidence is fixture/source identity and suite result; fallback is provider unreachable/trust stop. Any constraint widening requires an owner decision; the D11 contract itself is design-fixed.

## Test and evidence obligations

Run canonical record/identity unit vectors; conditional-head, stale-generation, duplicate, and malformed-frame contract tests; chain permutation and competing-controller tests; crash injection before append, after flush, after witness, and after lost ack; rollback/fork/witness-behind/ahead/mismatch/absence tests; restart/readback tests; hostile oversized/corrupt frame tests. `CF-MECH-LEDGER` oracle checks atomic expected-position behavior, flush-before-witness-before-ack, all five outcomes, a scripted monotonic witness whose separate logical control and fault surface model independent trust, and rollback restore detection. Record candidate content digest, source/fixture IDs, adapter build, manifest, environment, suite/probe versions, fixture-isolation/fault-surface metadata, timestamps, and results. Do not record real witness-topology qualification here; provider/E2E tests are omitted because no provider or product effect is reachable.

## Exact acceptance

An independent reviewer (not the author/adapter provider) reviews one complete candidate: commit/content digest; bounded Run-ledger contract and reference build; exact `CF-MECH-LEDGER` evidence package and crash corpus metadata; scripted witness binding, logical-control separation, and fault-surface evidence; delivery metadata and `pnpm check`/CI outputs. The evidence must not claim a real configured witness topology. Findings must be resolved; stale, partial, self-authored, or differently bound evidence rejects acceptance. Acceptance is a documentation/implementation-review verdict only, not landing; authoritative landing additionally requires the repository merge commit and required CI on that exact merged tree.

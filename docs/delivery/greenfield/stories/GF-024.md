# GF-024 — Witnessed idempotent intake and Run birth

## Outcome, value, and why now

Implement the sole witnessed terminal intake acknowledgement and Run birth point. Only accepted
`SCH-INTAKE-ACK.terminal-ack` derives `ID-RUN`; rejected terminal acknowledgement derives no Run.
This enables later controller lifecycle and dispatch but itself dispatches nothing.

## Governing paths and stable IDs

`CP-INTAKE` in `RT-OPERATOR` receives `EP-SUBMIT` through `PORT-INTAKE`; accepted output creates
`RT-CONTROLLER` only after witness verification. `SCH-ENVELOPE` is independently validated;
`SCH-INTAKE-ACK` is the terminal acknowledgement; accepted successor additionally commits
`SCH-INTAKE-CUT-CLAIM` at `LG-INTAKE`. `ID-RUN` is post-position derivation; `RT-WITNESS` covers
the intake head; `EV-ENVELOPE-SUBMITTED` is the submitted fact. `FC-INPUT` and `FC-TRUST` fail
closed; `CF-ENVELOPE`/`CF-MECH-LEDGER` prove it. `DR-4`/`DR-6` cannot weaken it. `PC-README-2`,
`PC-README-3`, `PC-JIG-1`, `PC-JIG-2`, `PC-JIG-3`, `PC-JIG-7`, `PC-JIG-13`, `PC-JIG-19`,
`PC-JIG-22`, `PC-JIG-23`, `PC-JIG-24`, `PC-CONCEPTS-1`, `PC-CONCEPTS-9` map boundary/envelope/
intake routes. `CFG-1`, `CFG-2`, `CFG-3`, `CFG-4`, `CFG-5`, `CFG-6`, `CFG-7`, `CFG-8`, `CFG-9`,
`CFG-10` bind configuration owner intent, never an intake bypass.

## Dependencies plus start evidence

GF-010 ledger, GF-011 recovery, GF-013 protected facts, GF-020 qualified source, and GF-023 exact
approvals must be merged/current on the baseline. Edges are respectively implementation,
implementation, implementation, evidence, and decision. Revalidate the exact envelope/proofs/
storage/witness basis; a submitted form, projection, or unwitnessed record is not start evidence.

## In-scope and non-goals

Scope is independent intake validation, canonical acknowledgement/claim staging, witnessed
conditional create/readback, Run-birth reconstruction, and successor contention/recovery. Run
lifecycle, scheduler, provider proof production, approval UI, and all dispatch/effects are excluded.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

`CP-INTAKE` is sole pre-Run caller of the intake store. It validates frozen inputs then commits one
acknowledgement or, for an accepted successor, one atomic acknowledgement-and-cut-claim pair at one
position. Store/witness are passive. The acknowledgement creates no authority before witness;
accepted tuple alone derives `ID-RUN`, rebuild basis, and controller start. Rejected ack creates no
Run. Builder/provider/preview/preflight record cannot write intake, transition, grant, decide,
publish, finalize, or dispatch.

## Observable success and terminal outcomes

Success is witnessed byte-equivalent terminal acknowledgement bound to exact composition, approval,
attempts, and frozen envelope. The only accepted/rejected terminal distinction before a Run is
`SCH-INTAKE-ACK.terminal-ack`, not a Story outcome. A rejected ack is durable evidence of no
`ID-RUN`; accepted successor pair is atomic and a same-cut contender receives a witnessed rejected
ack naming winner binding. No acknowledgement may dispatch an effect.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

`FC-INPUT` covers invalid envelope/preflight facts; `FC-TRUST` covers witness/head/pair/fork/winner
integrity. `CP-INTAKE` owns `BND-WAIT-LEDGER`: it starts when the exact composition-keyed
acknowledgement (and successor cut-claim pair where applicable) is conditionally submitted with its
expected intake head, uses the 30-second default within 1 second–5 minutes, and wakes only on a
witness-verified acknowledgement/readback. It never renews. Exhaustion enters pre-Run Recovery,
keeps the intake unaccepted, derives no `ID-RUN`, and never becomes a Story-level block or a
workaround.

Lost response reads the exact acknowledgement bytes. No acknowledgement means no Run and only
validated preflight-chain resumption; accepted acknowledgement with absent ledger rebuilds from
frozen bytes; rejected acknowledgement rebuilds neither. Pair missing companion, wrong position/
winner, witness-ahead, or unverifiable state fails closed and is never repaired half-by-half. This
story has no effect to retry or cleanup.

## Security and trust: validation, credentials, redaction, and authority widening

Validate canonical/versioned envelope, approval/proof/attempt binding, composition and cut key,
and exact digest domain. Credentials are not carried; diagnostics are redacted. Witness trust is
independent of intake/index/backups and advances only after flush before acknowledgement return.
No source, preview, approval, preflight record, or projection can widen intake authority.

## Deliverables without delegated algorithm invention

Deliver validator, staged ack/claim digest construction, atomic intake interface, witness/readback,
rebuild, second-winner recovery, and crash corpus. `DR-4` owner **Engineering + configuration**
selects transport only below fixed sole-caller/atomic semantics. `DR-6` owner **Engineering**
selects physical storage only below fixed pair/witness/readback semantics. Unavailable/fail-closed
is fallback; Arye owns widening and plan selection.

## Test and evidence obligations

Test accepted/rejected genesis, byte-equivalent same-digest replay, no-Run rejection, staged digest,
witness order/lost response, crash every boundary, rebuild, index-without-ack removal, successor
atomic pair/second winner, partial pair/fork/witness contradictions, and no dispatch. Record exact
envelope/approvals/attempts/ack/claim/head/witness/candidate/suite/probe metadata for both suites.
Lifecycle/product E2E is deferred.

## Exact acceptance

Independent review requires exact candidate/target, frozen envelope and proof package, ack/claim
bytes/digest domains, witness/storage basis, crash/contender corpus, findings, and delivery metadata.
No stale/self/partial package passes; acceptance is not landing and requires separate merge/CI proof.

## DR choices

`DR-4`: **Engineering + configuration**, typed intake/ledger transport under fixed atomicity and
witness ordering, fail-closed fallback. `DR-6`: **Engineering**, physical storage under fixed
pair/readback/trust rules, fail-closed fallback. Arye decides widening and plan selection.

## PR boundary, relative size, and split

`L`: one intake authority oracle. If reviewability fails, `GF-024a` may establish genesis path with
successor submission disabled, then `GF-024b` adds successor pair; ack and witness never split.

## Definition of Ready

- Every exact dependency edge, qualified source, approval, storage, and witness basis is current.
- Mapped IDs/routes/imports, sole authority, durable facts, recovery, and oracles are named.
- No pre-Run component can create a Run except accepted witnessed intake.

## Definition of Done

- Rejected terminal ack proves no Run; accepted ack is witnessed before return and alone births/rebuilds Run.
- Replay, contention, crash, recovery, integrity, and negative-dispatch evidence passes.
- Exact review, checks/CI, and `git diff --check` pass.

# GF-047 — Qualified local verification provider

## Outcome, value, and why now

Qualify the separate local-command verifier against GF-042 exact effect-free semantic contract, making only that exact manifest/build/environment configurable. Remote gates remain outside this story in GF-044. It cannot accept, choose policy, run effect-needing checks, or substitute for delivery; no qualification evidence transfers across provider build, manifest, environment, posture, or suite version.

## Governing paths and stable IDs

Mechanism/provider contracts owns capability manifest, qualification and CF-GATE-PROVIDER; review execution owns exact subject/effect-free verification. PORT-VERIFY is the sole local boundary, and OPC-VERIFY-EXECUTE is the controller-authorized, effect-free local check operation it carries. EV-CHECK-OBSERVATION, CF-MECH-VERIFY, CF-GATE-PROVIDER, and DR-5 map the result, qualification, and configuration boundary. `ID-OP` identifies one authorized local command observation and `ID-CAND` names its exact Candidate content/basis. FC-SUBJECT and FC-MECHANISM reject wrong subject and malformed mechanism fact; BND-WAIT-MECHANISM bounds a local observation wait. PC-JIG-8 requires independent reviewer authority, PC-JIG-15 provider-gated supported seams, PC-CONCEPTS-3 the same separation at concepts altitude, and PC-USE-5 a swap-safe qualified provider.

EARN-1 requires fresh positive capability proof and EARN-2 makes it specific to driver and run;
GUARD-1 freezes policy and GUARD-2 pauses rule-surface change. STACK-1 preserves guarantees across
vendors; STACK-2 fixes the four swappable seams; STACK-3 makes agent choice a profile choice;
STACK-4 requires attestation; STACK-5 keeps credentials/effects at authority seams; STACK-6 denies
first-party shortcuts; STACK-7 applies the same bar to custom providers. DRIVE-1 requires
conformance before trust; DRIVE-2 requires an approved manifest; DRIVE-3 reports the native posture
honestly; DRIVE-4 makes conformance reusable. These imports make a failed verifier unavailable,
not an outcome authority.

## Dependencies plus start evidence

Require merged GF-022 provider approval/proof machinery and GF-042 semantic contract/CER. Freeze owner-approved manifest, provider build, command allowlist and native posture, environment fingerprint, credential names, clean checkout/scratch/no-egress contract, suite/adversarial versions, and exact candidate vectors. Any drift makes provider unavailable.

## In-scope and non-goals

Scope is local command execution only. Exclude remote-gate observation or execution, semantic policy/check selection, acceptance, workspace/write/network effects, final delivery, real forge, and any alternate verifier/host. Remote gates remain in GF-044. Unsupported effect-needing check is rejected, not routed silently.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

Local verifier is PORT-VERIFY mechanism behind admitted capability binding; controller records intent then authorizes each effect-free OPC-VERIFY-EXECUTE under its ID-OP, frozen class/basis/fence, and ID-CAND; ledger persists the EV-CHECK-OBSERVATION. Provider receives read-only exact checkout, discarded scratch, permitted command/environment, no egress; it returns attestation only. It cannot mint authority, mutate subject, select class, or access delivery credentials.

## Observable success and terminal outcomes

Success is current exact CF-MECH-VERIFY pass plus CF-GATE-PROVIDER admission for this provider tuple; only then configuration may expose it. Observation pass/fail retains GF-042 semantics. Drift, failure, or expiry leaves the provider unconfigurable and any operation waiting on it parked or blocked according to its governing bound; this provider has no Story-outcome power.

Pending NotRun requires a direct Blocked/Rejected dependency, and Rejected requires the exact Story-bound owner reject-story action. It cannot accept/Land/release or make effects legal.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Command timeout/result loss is bounded by BND-WAIT-MECHANISM; expiry parks the provider observation without changing any Story outcome, and enforced effect-freedom makes replacement a new authorized ID-OP. Effect assertion, subject/fence/env mismatch, stale manifest, or malformed output is FC-SUBJECT/AUTHORITY/MECHANISM/EVIDENCE and fails closed. Recovery validates durable intent/receipt/result; no blind retry of uncertain external effect is possible because none is allowed; scratch is discarded safely.

## Security and trust: validation, credentials, redaction, and authority widening

Validate executable digest/allowlist, args/class, environment, checkout/basis/fence, capability proof age, provider identity, no egress/write and result limits. Credential names resolve only in provider memory and no forge credential is permitted. Redact/quarantine output; hostile command/output cannot widen manifest/authority. Remote-gate handling is excluded from this provider.

## Deliverables without delegated algorithm invention

Deliver local verifier adapter, manifest binding/admission, command/environment sandbox enforcement, qualification runner/CER, drift invalidation, and configuration reachability guard. DR-5 Configuration selects the local verifier only within the owner-approved plan profile; exact CF evidence is mandatory and fallback unavailable. Arye owns only widening beyond that approved selection. No algorithm beyond GF-042 contract is delegated.

## Test and evidence obligations

Contract tests exact command/class/basis/fence and no effect; adversarial tests write/network/escape, undeclared env/credential, wrong digest, stale proof, hostile output; replay/crash/timeout/replacement; provider qualification test exact build/manifest/environment/posture; E2E deterministic pass/fail only. Run complete CF-MECH-VERIFY and CF-GATE-PROVIDER with versioned CER.

## Exact acceptance

Independent reviewer freezes provider build, manifest/owner approval, environment/posture, command and authority limits, suite/adversarial/CER, drift and configuration guards, and exact GF-042 vectors. PASS admits only that tuple; it is not acceptance, landing, or proof for a changed provider.

## DR choices

DR-5 Configuration: owner-approved local verifier profile, exact manifest/build/environment and CF gate; alternatives need own provider story; fallback unavailable. DR-4 remains fixed by GF-042 and has no new choice.

## PR boundary, relative size, and split

M; provider realization only, deliberately split from GF-042 semantics. Expected adapter/manifest gate/qualification fixture/tests/config guard. Exclude policy, workspace, delivery, and other providers; no further split because one provider gate is the oracle.

## Definition of Ready

- Named predecessors are merged/current on selected baseline; exact subject evidence is frozen.
- IDs, port, principal/fence, durable facts, FC failures, finite BND bounds, recovery, oracle, DR, and PR boundary have independent readiness review.
- No unqualified provider/effect path is reachable and configuration cannot widen authority.

## Definition of Done

- Immutable inputs validate and stale, malformed, ambiguous, oversized, cross-scope, or self-attested facts fail closed.
- Intent precedes every effect; uncertain effects reconcile by stable identity and retry only after confirmed absence plus recorded reauthorization.
- Exact unit, contract, negative-authority, adversarial, replay, crash/timeout/recovery, provider-or-scripted, and E2E evidence passes; git diff --check, repository checks, CI, and independent exact-candidate review pass.

# GF-030 — Complete Run and Story lifecycle

## Outcome, value, and why now

Implement controller-owned replayable Run/Story state, dependencies, blocker roots, and the five product outcomes: Landed, Blocked, Rejected, NotRun, Stopped. GF-005 supplies the closed kernel, GF-011 fenced recovery, GF-024 witnessed Run birth. It enables scheduling only. Landed alone releases a dependency; Blocked and Rejected roots stay durable and dependents show their complete canonically ordered direct-root set.

## Governing paths and stable IDs

The lifecycle flow owns phase/outcome/containment; the catalogue owns all legal SCH-TRANSITION/SCH-EVENT edges. I13 preserves attributable non-delivery roots and I14 restricts release to confirmed landing. SCH-TRANSITION binds prior position, event, guard, authorizer, new position and next intent. DR-3 delegates reducer realization, never lifecycle semantics.

## Dependencies plus start evidence

Require merged GF-005 deterministic/illegal-edge proof, GF-011 fence/recovery proof, and GF-024 accepted SCH-INTAKE-ACK-to-ID-RUN proof on the selected baseline. Start packet records predecessor commit/tree, exact candidate/evidence digests, witness position, CI and independent verdict; a branch or assertion is not evidence.

## In-scope and non-goals

Scope: state projection, event/transition schemas, dependency attribution, containment, business-outcome versus retirement separation. Exclude capacity, bounds, workspace/session/Doorbell mechanisms, acceptance/review/publication/delivery, retirement and Settlement. Named future edges do not expose their ports.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

RT-CONTROLLER consumes versioned ID-RUN, ID-STORY, ID-EVENT, ID-GEN and validated ledger facts; witnessed ledger writes SCH-EVENT/SCH-TRANSITION and projections rebuild from it. Output is only the next catalogued intent, never a port call. Only current fenced controller transitions/proposes Operation; stores, providers, users and dependent Stories observe. Canonical identity/digest/generation binding rejects malformed, cross-Run or stale input as FC-INPUT, FC-SUBJECT or FC-FENCE.

## Observable success and terminal outcomes

Same accepted envelope and ledger prefix replay to same positions, event order, roots and release set. Landed is unreachable until GF-044 landing proof. Blocked, Rejected and NotRun are durable no-release outcomes; Stopped is only a later trustworthy terminal path, never guessed from failure. Parked, Suspended, Recovering and Settling are nonterminal, and retirement cannot revise outcome.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Illegal containment is FC-INPUT/FC-SUBJECT; stale generation FC-FENCE; unreadable/forked authority FC-TRUST and Recovery, not Stopped. This story dispatches no effect. Later effects record stable ID-OP intent first and reconcile under GF-015/GF-032; uncertain effects are never blindly retried. Recovery reconstructs witnessed facts under new generation. Preserve state; cleanup/obligations remain GF-038/GF-046/GF-050.

## Security and trust: validation, credentials, redaction, and authority widening

Use canonical bounded codecs, identity/digest/fence validation and witness readback. No credential is resolved; logs/projections hold IDs/digests, never secrets. Malformed, ambiguous, self-attested or unverifiable facts fail closed. Provider result, configuration and fallback cannot author transition or widen authority.

## Deliverables without delegated algorithm invention

Deliver reducer/projections, versioned schemas, transition/outcome/dependency fixtures, and CF recorder updates in GF-001/004-selected paths. DR-3 owner Arye Kogan selected closed controller reducer; immutable constraints are catalogue, record-before-adopt, I13/I14 and controller-only authority. Provider-owned lifecycle is rejected; gap is OWNER_DECISION_REQUIRED; blast radius is all controller stories.

## Test and evidence obligations

Run exhaustive legal/illegal edges, five-outcome/dependency permutations, negative authority, duplicate/stale events, crash-prefix replay and recovery. Evidence records fixture/input/candidate/tree/source digests, witness position, runner/version/time/result. CF-BLOCKERS, CF-RELEASE, CF-CONTAINMENT, CF-RUN-CONTROL are required. Provider/timeout/effect E2E is inapplicable because no port dispatches.

## Exact acceptance

Independent non-author checks exact candidate/tree/baseline, matrices, evidence/CI metadata and findings. In phase 3 this is semantic evidence only: GF-040 alone accepts; GF-044 alone proves landing. Partial, self-authored, stale or differently bound proof fails closed.

Size L; one cohesive oracle is exhaustive lifecycle replay. Paths: reducer/projection, schemas, fixtures, CF evidence; exclude ports/providers/Settlement. Split GF-030a contract/kernel from GF-030b projections only if both remain green and no effect configures.

- Recovery/negative evidence passes and no effect dispatches.
- Exact-candidate diff check, repository checks, CI and independent review pass.

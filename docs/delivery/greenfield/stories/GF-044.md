# GF-044 — Final delivery semantic protocol

## Outcome, value, and why now

Implement scripted final delivery: exact operation protocol, effect certainty, policy-selected integration modes, authoritative target observation, content-equivalent landing proof, and dependency release only after Landed. It needs GF-015/030/040/043 and has no real GitHub provider or block surfacing; acceptance is never a substitute for landing.

## Governing paths and stable IDs

Forge and landing owns seven delivery operations, integration modes, LP-EQUIV and LP record; acceptance/evidence states delivery success is not landing proof. The listed events bind target/effect/landing facts; CF-RELEASE, CF-DOUBLE-EFFECT, and finalization CF-MECH-DELIVERY prove the protocol.

`RT-CONTROLLER` is the delivery writer through `PORT-DELIVERY`; `OPC-DEL-ANCHOR`,
`OPC-DEL-PUBLISH`, `OPC-DEL-REQUEST`, `OPC-DEL-STATUS`, `OPC-DEL-COMMENT`, `OPC-DEL-MERGE`, and
`OPC-DEL-OBSERVE` are the complete operation set. `EV-TARGET-FACT`, `EV-EFFECT-CERTAINTY`, and
`EV-LANDING-OBSERVED` are durable attested facts. `RP-REMOTE` is strictly a remote gate
observation delivered through PORT-DELIVERY and OPC-DEL-OBSERVE, never a local check. `ID-OP` is
the immutable identity of each authorized delivery operation; `ID-TARGET` names the one
authoritative integration target; and `ID-AUTH` is the current finalizer fence scoped to that
target, Candidate basis, and registry realization. `LP-OBSERVE`,
`LP-RESOLVE`, `LP-COMPARE`, `LP-EQUIV`, `LP-HELD`, and `LP-RECORD` observe, resolve, compare, hold,
and record proof; `FC-EFFECT`, `BND-WAIT-TARGET`, and `target_stability` contain uncertainty/wait.
`CF-RELEASE`, `CF-DOUBLE-EFFECT`, and `CF-MECH-DELIVERY` are the proof. `PC-JIG-1`, `PC-JIG-25`,
and `PC-CONCEPTS-2` carry governed delivery, isolation, and dependency-release commitments.
`MERGE-1` requires independent policy-aligned evidence; `MERGE-2` reserves push, PR creation, and
merge to the runner; `MERGE-3` makes done conditions policy-bound; `MERGE-4` separates done from
merged; and `MERGE-5` requires safe Blocked-work surfacing.

## Dependencies plus start evidence

Freeze merged predecessor evidence plus Accepted package, current ID-AUTH/registry/anchor, Candidate/basis/changed-path digests, frozen integration strategy, delivery manifest, correlation keys, and PORT-DELIVERY remote gate/target facts. Any target/basis/rule/policy/authority change invokes GF-043 refresh/re-review; scripted provider only.

## In-scope and non-goals

Scope is anchor/publish/request/status/comment/merge/observe semantic protocol, effect reconciliation, LP observation-resolve-compare-record, and release. Exclude acceptance/reviewer, finalizer ordering, real provider admission, block surfacing, retirement, policy selection, and target mutation outside protocol.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

CP-FINALIZER under current ID-AUTH proposes each Transition-authorized PORT-DELIVERY operation; controller/ledger record intent, certainty, observation, and proof. Inputs bind ID-OP/fence, Candidate/basis, mode, anchor/registry, gate and correlation facts. Provider attests only; it cannot grant authority, alter policy, set Landed, or release. Only LP-RECORD after authoritative target observation and LP-EQUIV writes Landed/release.

## Observable success and terminal outcomes

Success is durable Landed with authoritative post-effect target fact, strategy-specific content equivalence, registry identity, and immediate dependent release. Publish/request/pass gate/provider response alone is not success. Held integration remains named BND-WAIT-TARGET; contradictory/indeterminate effect parks; Blocked/Rejected/NotRun/suspension preserve non-delivery and do not release.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Record intent first. Uncertain anchor/publish/request/status/comment/merge reconciles by its stable correlation lookup and post-effect target observation; never blindly replay. Only confirmed absence plus reauthorization retries same effect. Observations are new authorized operations. FC-EFFECT/MECHANISM/SUBJECT/AUTHORITY/EVIDENCE and finite wait/retry bounds fail closed; recovery reobserves before dispatch. Preserve target/request resources for GF-046.

## Security and trust: validation, credentials, redaction, and authority widening

Validate canonical target/ref/Candidate/basis/mode/fence/correlation and fresh authoritative attestation; reject missing/ambiguous/stale/cross-binding facts. Credentials resolve only by name in provider memory. Ledger/view stores redacted correlation identifiers, never token/signed URL; bound/redact hostile provider text. Scripted adapter cannot configure; provider facts cannot widen authority.

## Deliverables without delegated algorithm invention

Deliver typed delivery operation/effect/observation schemas, integration-mode and LP-EQUIV evaluators, controller guards, scripted delivery provider, reconciliation/recovery matrix, and CF catalog. DR-4 selects typed semantic port plus edge transport, exact contract evidence, unavailable fallback. No delivery strategy or acceptance rule is invented beyond frozen policy.

## Test and evidence obligations

Unit/schema tests every operation/mode/equivalence rule; contract tests exact fence/correlation/anchor; negative authority rejects merge without grant and release without LP record. Adversarial tests wrong target/basis/mode, anchor race, forged gate, secret output; replay/crash tests every before/after effect; E2E scripts fast-forward/merge/squash/queue equivalents, held, uncertain, no double effect. Record exact CER and run all three CF suites.

## Exact acceptance

Independent reviewer freezes candidate/tree, Accepted package, grant/anchor, mode, operation intents, correlation/effect certainty, authoritative target observation, LP-EQUIV evidence, release trace, failures/recovery, DR and CF CER. PASS is exact implementation acceptance; Landed is valid only per LP-RECORD on the runtime exact subject.

## DR choices

DR-4 Engineering plus configuration: typed PORT-DELIVERY edge, no provider reachability without CF gate; exact contract and CF proof; fallback unavailable. DR-5 is deferred to GF-061.

## PR boundary, relative size, and split

L; one final-delivery/landing oracle across scripted protocol, not real provider. Expected paths delivery contracts, LP evaluator, guards, fixture, tests. GF-044a observation/equivalence may split from effect operations only if both remain green and unconfigurable; exclude GF-045/046.

## Definition of Ready

- Named predecessors are merged/current on selected baseline; exact subject evidence is frozen.
- IDs, port, principal/fence, durable facts, FC failures, finite BND bounds, recovery, oracle, DR, and PR boundary have independent readiness review.
- No unqualified provider/effect path is reachable and configuration cannot widen authority.

## Definition of Done

- Immutable inputs validate and stale, malformed, ambiguous, oversized, cross-scope, or self-attested facts fail closed.
- Intent precedes every effect; uncertain effects reconcile by stable identity and retry only after confirmed absence plus recorded reauthorization.
- Exact unit, contract, negative-authority, adversarial, replay, crash/timeout/recovery, provider-or-scripted, and E2E evidence passes; git diff --check, repository checks, CI, and independent exact-candidate review pass.

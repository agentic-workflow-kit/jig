# Risks and owner decisions

## Design constraints and inactive delivery defaults

The design imposes authority, port, contract, conformance, and fail-closed boundaries. It defers
package layout, framing/wire realization, provider implementation, and profile selection within
those boundaries. The following delivery posture is therefore proposed, not owner-approved by this
corpus. It becomes selectable only when an explicit current owner or named-delegate implementation
request selects the bounded choice, as defined in
[the delegated-choice schedule](./decisions.md#implementation-authorization).

| Delivery choice or approved authority | Design boundary that remains binding                                                                                                  | Activation and delivery consequence                                                                                                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Private topology                      | D10 fixes modular single authority and defers package/module layout.                                                                  | Node/TypeScript/pnpm/Turbo may start GF-001/GF-003 only when explicitly selected; graph proof cannot select it.                                                                                        |
| Boundary framing                      | D12/D16 defer wire/physical representation within their validation and conformance constraints.                                       | Strict JSON may start GF-002 only when explicitly selected; ambiguous/alternative framing remains unavailable.                                                                                         |
| Durable truth                         | D11 owner-approves the conditional-append contract, single-host append-only file reference realization, and independent witness rule. | Only segment sizing, batching, and directory layout remain deferred; no autonomous restore without the required independent witness evidence.                                                          |
| Initial providers                     | D12 keeps every provider unconfigurable until its exact mechanism proof is admitted.                                                  | The proposed source/store/workspace/verifier/session tuple plus disjoint GitHub review-publication and final-delivery providers/credentials needs explicit selection and separate qualification gates. |
| Notice channel                        | DR-12 keeps notice a durable presentation concern, not a provider authority path.                                                     | Terminal/file presentation needs explicit selection plus notice/block-surfacing evidence; it is not `CF-GATE-PROVIDER` proof.                                                                          |
| Provider posture                      | Unqualified or unsupported paths must remain unreachable.                                                                             | No compatibility inference, partial mode, or fallback makes a provider configurable.                                                                                                                   |
| Consumer surface                      | D10's private facade cannot create another lifecycle authority or public stability promise.                                           | Proposed CLI/private MCP surfaces need explicit selection; GF-054–056 still prove parity and scope.                                                                                                    |

No entry above selects itself. An explicit current request to implement a named phase/story is
sufficient implementation authorization within current product/design/track authority. It selects
only the bounded defaults it names or necessarily incorporates. Genuine authority, scope,
realization, or provider-reachability ambiguity is `OWNER_DECISION_REQUIRED`.

## Escalation boundary

The ten open decisions are exactly DR-1 through DR-9 and DR-12. DR-10 and DR-11 are closed
constraints. A request to alter a fixed ID, authority boundary, lifecycle result, provider power,
policy floor, or conformance input is not an implementation choice; it requires an explicit owner
decision. Choosing a proposed bounded default requires explicit current owner or named-delegate
direction for the named phase/story. Once delivery starts, record that scope, its constraints, and
the selected realization in the external operational ledger. No package digest, separate approval
issue, or historical approval claim substitutes for current product/design authority or explicit
scope.

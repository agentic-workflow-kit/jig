# GF-061 — Qualified GitHub final-delivery provider

## Outcome, value, and why now

Qualify the GitHub adapter only for post-acceptance final delivery: `CP-FINALIZER` proposal,
recorded `CP-TRANSITION` authorization, current `ID-AUTH`, exactly the seven `OPC-DEL-*` effects,
target readback, and exact reconciliation. It is a distinct provider/PR authority subject from GF-057's
pre-acceptance review-publication provider and permits only the selected final-delivery profile
after proof. It cannot make review publication, queue/held/unknown modes, or a fallback target
path configurable.

## Governing paths and stable IDs

`mechanism-and-provider-contracts.md` owns provider qualification, `forge-and-landing.md` owns
the final-delivery target effect/readback contract, `lifecycle-catalogs.md` owns the exact operation
families, authorizing transitions, lifecycle, and handoff rules, and `data-and-identity.md` owns
`ID-OBLIGATION` identity. `DR-4`/`DR-5` delegate selected
configuration/mechanism only; final target effects remain proposed by `CP-FINALIZER` and authorized
only by recorded `CP-TRANSITION`. D15 review publication is exclusively GF-057's subject and supplies
neither authority nor qualification evidence here.

Local mapping: `PORT-DELIVERY` is the final GitHub seam. `CB-DELIVERY` binds one repository,
target ref, exact Accepted Candidate content/basis, current `ID-AUTH`/registry lineage, admitted
provider manifest/credential class, and only the seven `OPC-DEL-*` classes. `CP-FINALIZER`
proposes, `CP-TRANSITION` alone authorizes, and `CP-MEDIATOR` validates that complete
subject/resource/capability binding before dispatch and fact adoption. It cannot cross repository,
target, Candidate, basis, authority, registry, manifest, credential, generation, or Operation;
cannot admit any `OPC-REV-*`; and cannot reuse review-publication, verification, workspace, or
session binding. `DR-4`/`DR-5` bind configuration/provider;
`FC-MECHANISM`/`BND-WAIT-MECHANISM` contain confirmed pre-uncertainty API fault;
`BND-RETRY` bounds only confirmed-absent replacement; `BND-RECOVERY` contains uncertain effects;
`EV-TARGET-FACT` and
`RP-REMOTE` bind remote target observation; `OPC-DEL-ANCHOR`, `OPC-DEL-PUBLISH`,
`OPC-DEL-REQUEST`, `OPC-DEL-STATUS`, `OPC-DEL-COMMENT`, `OPC-DEL-MERGE`, and
`OPC-DEL-OBSERVE` are the complete recorded final-effect set; `ID-OP` binds each stable
reconciliation identity; `ID-TARGET` binds the observed target; current `ID-AUTH` is required for
every final action; and any `ID-OBLIGATION` here identifies only a preserved residual-duty handoff,
never review-retirement authority. `CF-SECRET-ABSENCE`, `CF-MECH-DELIVERY`,
`CF-BLOCK-SURFACING`, and `CF-GATE-PROVIDER` prove final-provider admission. `PC-JIG-8`,
`PC-JIG-15`, `PC-JIG-21`, `PC-CONCEPTS-3`, `PC-CONCEPTS-5`, and `PC-USE-5` close through the
independently qualified final capability. `MERGE-1`, `MERGE-2`, `MERGE-3`, `MERGE-4`, `MERGE-5`,
`SEC-1`, `SEC-2`, `SEC-3`, `STACK-1`, `STACK-2`, `STACK-3`, `STACK-4`, `STACK-5`, `STACK-6`,
`STACK-7`, `DRIVE-1`, `DRIVE-2`, `DRIVE-3`, and `DRIVE-4` close through exact remote reconciliation,
credential separation, and delivery evidence. `MERGE-5` closes here only for the post-acceptance
`OPC-DEL-*` landing venue and exact residual `ID-OBLIGATION` handoff; GF-057 alone qualifies the
`OPC-REV-*` publication and retirement provider behavior.

## Dependencies plus start evidence

Require exact merged GF-022 provider authority, GF-043 target authority, GF-044
delivery/reconciliation, and GF-045 Blocked-surfacing evidence. Freeze GitHub API/build, provider
manifest, repository/target basis, final credential reference/scope, branch protection/mode, stable
final-effect marker format, selected host/environment, and predecessor suite digests. Any
absent/stale/substituted proof, held/queue mode, permission overlap, or review-provider substitution
leaves the final-delivery provider unavailable.
Qualification additionally requires the exact external activation record; exact pre-verdict
candidate identity `Q`; full external review record `R`; approved package tuple
`P = Q + durable R identifier + PASS`; authoritative landing-equivalence record; and separately
observed execution-base ref, commit, tree, and predecessor containment. Immutable planning
provenance alone is not an execution authorization.

## In-scope and non-goals

In scope: real adapter qualification for the seven authorized post-acceptance `OPC-DEL-*`
operations, authoritative readback, and final-delivery-scoped Blocked surfacing. Exclude every
`OPC-REV-*` operation and every review-venue retirement effect, pre-acceptance publication, worker
or reviewer forge credential access, generic GitHub automation, merge-queue/held mode support,
public API surface, credential sharing, and policy/acceptance changes.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The adapter mediates final `PORT-DELIVERY` facts/effects. Every action requires the recorded
finalizer proposal/Transition authorization, exact `ID-AUTH`, exact `ID-TARGET`, Candidate content
digest, target basis, current controller generation, provider manifest, and stable final-effect
marker. Durable `ID-OP` operation intent, effect identity, observed target state, receipt/failure,
candidate delivery metadata, and any exact `ID-OBLIGATION` handoff fact are truth. The final
credential has only the selected final effect scope and is never given to worker or reviewer. GitHub observations cannot
declare acceptance or release dependencies; authoritative target proof is required for landing.

A coexisting review-venue residual duty remains a controller-owned `ID-OBLIGATION`; GF-061 may
preserve only its exact handoff reference in delivery metadata for GF-046's duty model and execution
through GF-057's review-publication provider. It cannot inspect the review venue or authorize,
dispatch, reconcile, complete, or claim any `OPC-REV-*` retirement effect.

Remote delivery evidence is not local-verifier evidence: the adapter dispatches the recorded
`OPC-DEL-OBSERVE` through `PORT-DELIVERY`, validates an exact `RP-REMOTE` observation against the
Candidate/target/manifest/fence, and commits `EV-TARGET-FACT` before any landing conclusion. The
local verifier remains solely under `PORT-VERIFY`; neither it nor a GitHub response owns delivery.

## Observable success and terminal outcomes

Success is current-profile GitHub evidence showing exact final effect/readback only after finalizer,
Transition, and `ID-AUTH` gates. Every external effect is idempotent or discoverable by its stable
marker. GF-057 qualification is required separately for any review publication; this provider cannot
publish a draft review request. Unknown/held/queue/ambiguous results are `Blocked` or `Parked`
according to existing containment and retain authority fence; no `Landed` occurs without
authoritative target proof.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Map malformed, unknown, noncanonical, oversized, or version-skew Candidate/ref/marker input to
`FC-INPUT`; wrong Candidate/ref/path/target subject to `FC-SUBJECT`; stale controller/authority fence
to `FC-FENCE`; scope breach to `FC-AUTHORITY`; invalid remote proof to `FC-EVIDENCE`; confirmed
GitHub/API failure or timeout before effect uncertainty to `FC-MECHANISM`; and a lost, late,
conflicting, or unverifiable result after dispatch to `FC-EFFECT`. Record each exact final-delivery
Operation intent and deadline before dispatch.

`CP-MEDIATOR` starts `BND-WAIT-MECHANISM` with the durable request; its 15-minute default (range 5
seconds–2 hours) never renews and wakes only on a validated result, confirmed mechanism failure, or
effect-certainty observation. A confirmed mechanism failure/timeout may consume the next
`BND-RETRY` ordinal only after exact stable-marker/target observation proves absence and the
controller records reauthorization. `BND-RETRY` has three attempts by default (range 1–5), records
every ordinal, never resets, and exhaustion with confirmed absence and no effect uncertainty
directly blocks the owning Story/Operation.

An `FC-EFFECT` result retains the exact Operation/`ID-AUTH` fence and starts `BND-RECOVERY` under
`CP-RECOVERY`. Reconcile only by stable marker plus authoritative target observation. The recovery
bound has three observations by default (range 1–5), never renews, wakes only on
`EV-RECOVERY-OBSERVATION` or `EV-EFFECT-CERTAINTY`, and permits no semantic-effect retry.
Exhaustion parks/escalates while retaining the fence and target/request resource.
`BND-WAIT-TARGET` separately bounds confirmed held target state and cannot authorize a retry.
Recovery preserves any exact residual review-venue `ID-OBLIGATION` handoff for GF-046/GF-057
without dispatching it. Uncertain cleanup preserves the resource and handoff fact. No provider
reconnect resumes an unauthorized final effect or crosses into an `OPC-REV-*` capability.

## Security and trust: validation, credentials, redaction, and authority widening

Canonicalize repository/target/marker/Candidate digest, validate API response binding and current
manifest, and enforce credential-class disjointness from GF-057 in configuration and runtime. Final
credential names resolve in memory only with least scopes; secrets/tokens/raw headers are excluded
from ledger/evidence/export/logs. Redact provider metadata as policy requires. Unverifiable API
result, mode, scope, or proof fails closed. No GitHub response or fallback can mint `ID-AUTH`,
acceptance, finalization, or landing authority.

## Deliverables without delegated algorithm invention

Deliver a private GitHub final-delivery provider adapter, final credential/profile validator, exact
target/marker mapper, final-effect reconciler, mode gate, read-only residual-obligation handoff
recorder, sandbox repository fixtures, and qualification recorder. The handoff recorder preserves
an exact `ID-OBLIGATION` for GF-046/GF-057 and has no review-retirement dispatch capability. `DR-4`
is implemented by Engineering + configuration and `DR-5` by Configuration; their work requires the
exact external activation record, exact pre-verdict `Q`, full external review record `R`, approved
`P = Q + durable R identifier + PASS`, landing-equivalence record, and separately observed
execution-base ref/commit/tree with predecessor containment, while widening remains an owner
decision. Constraints are finalizer-only authorization and credential separation from GF-057;
evidence is real matrix; fallback is provider unavailable.
New mode, scope, merge policy, or credential model is `OWNER_DECISION_REQUIRED`.

Run real sandbox-repository tests for credential disjointness from GF-057, exact
Candidate/target/marker binding, finalizer/Transition/`ID-AUTH` prerequisites, denied review-scope
operations, idempotent discover/reconcile matrix, timeout/API failure/unknown outcome, stale

`CF-MECH-DELIVERY`, `CF-BLOCK-SURFACING`, and
`CF-GATE-PROVIDER` with exact build/manifest/repo/mode/fixture/output digests. Landing E2E is
included only for authorized sandbox target proof, never by GitHub assertion alone.

## Exact acceptance

Independent reviewer receives exact candidate/target/provider/final-credential/mode digests, redacted
real-provider evidence, marker reconciliation traces, and suite results. Any credential overlap with
GF-057, target effect before gate, review-scope operation, unreconciled uncertain effect, or enabled
held/queue mode fails. Acceptance is not the authoritative merged landing proof.

## DR choices

`DR-4` implementation owner is Engineering + configuration and `DR-5` implementation owner is
Configuration. The exact external activation record, exact pre-verdict `Q`, full external review
record `R`, approved `P = Q + durable R identifier + PASS`, landing-equivalence record, and
separately observed execution-base ref/commit/tree with predecessor containment authorize the
recorded GitHub final-delivery profile; any widening remains an owner decision. The finalizer-only,
real-evidence, credential-separation, and provider-unavailable boundaries apply.
Rejected alternatives are shared credential, worker publishing, review-capability substitution, or
queue/held support. No new DR applies.

## PR boundary, relative size, and split

L, one final-delivery provider qualification. GF-057 is the already-separated review-publication
PR authority subject; do not combine them because their authorizing transitions, credentials, allowed
operations, and evidence are independently reviewable. No review-retirement dispatch path belongs
to this authority subject.

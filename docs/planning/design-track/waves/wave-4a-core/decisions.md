# Wave 4a — decision log

Records `D-###` dispositions from framing and design-review for this wave (the four CORE parts:
`w4-s1` records/observability, `w4-s2` plan/policy/evidence, `w4-s3` authority-spine,
`w4-s4` bootstrap/composition-root). D-001..D-006 are the coordinator's frame-gate dispositions over
the four per-part `InputResolution` reports; the Disposition column names the resolved choice and the
Rationale gives the source evidence. Later `D-###` entries record `review-technical-design`
(build-time QA) suggestion dispositions (`fix`/`reject`/`defer`) raised over this wave's scaffold.
D-### IDs are wave-scoped: a reference to another wave's decision names the wave (e.g. "Wave 2's
D-003"), never a bare `D-###`.

Wave 4 is framed **per part**, not with one wave frame — the four frames live in `frames/` (mirroring
`stories/`). This is a navigable, deliberate deviation from the prior one-`frame.md`-per-wave shape,
justified by the plan's "Wave 4 gets a frame per part" instruction (each core seam is its own design
problem). The 4a/4b split is a separate commit unit each: `wave-4a-core/` (this unit) and, later,
`wave-4b-providers/` — 4b's frames consume 4a's committed output, so they cannot be one unit.

## Design-review dispositions (per-unit review)

The per-unit `review-technical-design` pass over this scaffold (three lenses at scaffold altitude +
the planning checklist) returned **APPROVE** — zero blocking findings. Depths, GUARD-2 identical
wording (byte-diffed s2 vs s3), the cross-part seam wording (s1↔s4, s3↔s4), `depends_on` ↔
`story-dag.md`, deepen-in-place, INV-009+ un-numbering, and 30/30 wave-qualified `D-###` references
all verified clean. An independent read-only fidelity audit (peer session) separately confirmed all
story claims against the cited jig sources: no invented product IDs, no `INV-*` renumbering, no
distorted source quotes. One disposition recorded:

- **D-007** — Per-unit review (agreement-integrity, **recommended**): the charter's per-part ID gloss
  on the `docs/product/guarantees.md` input-doc line diverged from the stories' authoritative
  `reconciles_to` frontmatter — s2 overstated (`MERGE-1..5`/`CFG-1..10` implied IDs it does not own),
  s3 understated (omitted `GUARD-1/2`, `EARN-1/2` that s3 actually reconciles to and that the
  charter's own GUARD-2 narrative already attributes to it — an internal inconsistency).
  **Disposition: fix.** Routed through the same implementer (coordinator does not hand-edit authored
  content): each of the four glosses was rewritten to the story's exact `reconciles_to` product-ID
  set, `..N` ranges expanded to explicit enumerations so no range implies an unowned ID, with the
  `INV-*` members deliberately kept on the `runtime-design-m5a.md` line to preserve the three-namespace
  separation. Coordinator verified all four glosses now equal their story frontmatter product-ID sets
  exactly (programmatic set-compare, order-independent).
- **D-008** — `w4-s1` build-time review S-001 (architecture-enforceability, **blocking**): the
  Records design delegated redaction/export posture to upstream classification without saying what
  happens when the posture is missing, unknown, or ambiguous.
  **Disposition: fix.** Records must fail closed: reject governed appends without valid
  redaction/export posture, deny or constrain inspect/export until posture is valid, and omit or
  redact secrets before record persistence rather than only before surfacing.
- **D-009** — `w4-s1` build-time review S-002 (agreement-integrity, **blocking**): the Records design
  did not state the Wave 4a D-004 records-store construction seam with `w4-s4`.
  **Disposition: fix.** `records.md` must state that Records owns the store shape, consistency model,
  and invariants, while Bootstrap owns constructing and wiring the store at launch, including the
  first binding-record append, without redesigning Bootstrap.
- **D-010** — `w4-s2` build-time review S-001 (agreement-integrity, **recommended**): the
  plan/policy/evidence design named Wave 4b execution-host framing only generically, while the story
  requires the downstream consumer to be citable as `w4-s6-execution-host`.
  **Disposition: fix.** `plan-intake.md` must name `w4-s6-execution-host` directly as the
  frame-time consumer of the evidence/attestation model.
- **D-011** — `w4-s4` build-time review S-001 (architecture-enforceability, **blocking**): the
  Bootstrap design added technical-design frontmatter and a Planner Handoff Summary, but the summary
  lacked the required source-closed handoff shape.
  **Disposition: fix.** `bootstrap.md` must reshape the handoff summary to include identity,
  `SRC-*` rows, unique stable IDs for planner-facing facts, and explicit `ENF-*`, `DEL-*`, and
  `FILE-*` rows or source-backed `None` entries, while keeping invariant facts candidate-only.

# GF-021 — Envelope policy, profiles, setup, and bounds

## Outcome, value, and why now

Deliver pure, immutable envelope composition: policy floors, named work profiles, setup
declarations, versioned guidance, and every declared bound default/range. It makes a proposal
reviewable before real providers and intake, while preserving floors and finite waits. It does not
execute setup, obtain authority, prove a provider, approve a proposal, or create a Run.

## Governing paths and stable IDs

`envelope-production.md` owns `EP-FLOORS`, `EP-PROFILE`, `EP-SETUP`, `EP-GUIDANCE`, `EP-COMPOSE`,
proposal-digest composition, and the rule that setup is declared rather than executed.
`scheduling-and-bounds.md` owns all `BND-*` defaults/ranges/exhaustion; `data-and-identity.md`
owns `SCH-WORK-PROFILE`, `SCH-CONFIG-ARTIFACT`, and the later `SCH-SETUP-RECEIPT` shape.
`delegation-register.md` limits `DR-9` to tuning inside frozen ranges. `CF-POLICY` and
`CF-SETUP-FRESHNESS` are the exact oracles.

## Dependencies plus start evidence

Require merged GF-002 canonical schema/identity evidence, GF-004 evidence recorder, and GF-019's
validated scripted `SCH-PLAN` contract on the exact baseline/tree. Reconfirm every bound table,
policy floor, and profile rule from current governing paths and verify the source remains scripted
unless GF-020's separately qualified provider is selected. An unreviewed config, prose preset, or
future setup receipt is not start evidence.

## In-scope and non-goals

In scope: floor-tightening proof; strict policy/profile/config-artifact/setup-recipe declarations;
composition/proposal digest; capacity/reserve and all bound defaults/ranges; and non-authoritative
guidance/preset resolution. Exclude setup command or workspace execution, config-artifact I/O,
receipt production, capability proof, manifest approval, provider realization, preview/owner
approval/intake, Run creation, scheduling dispatch, and changing any floor/semantic bound.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The external Builder receives owner/track declarations and a GF-019 plan, validates them, and emits
a canonical composition report and unapproved proposal digest. `SCH-WORK-PROFILE` names model/
provider, effort, prompt-strategy, role realization, and only cataloged durable qualifying
checkpoints; `SCH-CONFIG-ARTIFACT` binds exact content/digest; `SCH-SETUP-RECEIPT` is referenced as
a future effect output, never written here. Track author/owner may supply bounded inputs; Builder
may validate/compose/explain, never approve, execute setup, read an artifact, create `ID-RUN`,
append, grant, or dispatch. Guidance is a projection and cannot be a hidden default.

## Observable success and terminal outcomes

Success is a deterministic proposal basis binding one track, exact plan, composed floor proof,
named profile/artifacts, declared setup fingerprint rule, capacity/reserve feasibility, and every
chosen bound/range version. It releases an unapproved proposal only. Unknown or weakened floor,
profile/checkpoint/artifact/setup rule, out-of-range value, incompatible capacity, or cross-track
input is `Rejected`/`NotRun` before approval. No setup receipt, capability proof, approval, Run,
ledger record, or dispatch can result.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

Invalid/unknown/noncanonical inputs are `FC-INPUT`; an unexpressible checkpoint or weakened rule
is `FC-RULES`; wrong binding is `FC-SUBJECT`; unavailable referenced evidence is `FC-EVIDENCE`.
There is no I/O or effect to retry. Declared configuration-artifact reads and setup execution occur
only later: their `BND-WAIT-MECHANISM` 5s–2h and `BND-RETRY` 1–5 must be frozen, never consumed
here. Pure recomputation from immutable declarations is recovery; mismatch produces a new proposal.
No allocations require cleanup or resume.

## Security and trust: validation, credentials, redaction, and authority widening

Reject unknown versions/rules, duplicate/noncanonical maps, oversized artifacts, credential values,
unbounded ranges, hidden defaults, cross-track/profile/provider references, and any floor reduction.
Store only credential names in later manifests; this story resolves none. Redact prompts/guidance
diagnostics and keep artifact digests/fingerprints as evidence. Profile, preset, setup declaration,
and policy are untrusted until validation and never grant provider, workspace, or Run authority;
no adapter is configured by this story.

## Deliverables without delegated algorithm invention

Deliver immutable schemas, pure composition/floor proof, profile/preset/setup-declaration
validators, bound catalogue/range validator, guidance renderer, fixtures, and conformance records.
`DR-9`: Configuration/policy may select numerical values only within design-owned class ranges and
defaults, evidenced by boundary probes; fallback is preflight rejection. It cannot invent a new
bound, renewal, exhaustion action, reserve rule, checkpoint, policy weakening, or setup behavior.

## Test and evidence obligations

Run canonical/determinism vectors; floor preservation/tightening and unknown-rule negatives;
profile/provider/posture/checkpoint/artifact compatibility tests; all default/min/max/out-of-range
bound probes; capacity/reserve/path feasibility permutations; setup fingerprint/declaration
freshness fixtures; guidance-not-authority tests; replay of proposal digest; and no-I/O/no-Run/no-
dispatch authority tests. Record policy/profile/artifact/setup/bound catalogue digests, fixture and
candidate identity, suite/build/probe metadata for `CF-POLICY` and `CF-SETUP-FRESHNESS`. Provider,
crash, and E2E effect tests are inapplicable because all behavior is pure.

## Exact acceptance

An independent reviewer checks the exact content/baseline digest, policy/profile/bound catalogue
and fixture digests, composition vectors, suite metadata and findings, and delivery metadata.
They require exact-subject deterministic verification and no open findings. Their acceptance does
not approve a later envelope or land code; merge/CI proof is separate, and stale/partial/self review
fails closed.

## DR choices

- `DR-9` — Configuration/policy; selected values are immutable per envelope and inside published
  ranges; `CF-POLICY` boundary vectors prove it; out-of-range input rejects. No other `DR-*` is
  delegated here, because setup/provider algorithms are expressly excluded.

## PR boundary, relative size, and split

`L`, one deterministic composition oracle. Expected paths are policy/profile/setup-declaration,
guidance, bounds, fixtures, and evidence. Split `GF-021a` composition/bounds from `GF-021b`
guidance only if guidance is independently packaged while sharing identical validators; setup
execution and artifact reads are excluded, not a split.

## Definition of Ready

- Exact GF-002/GF-004/GF-019 merge evidence and governing bound/floor catalogue are current.
- Inputs, principals, durable future facts, authority fences, failure types, and `CF-*` oracles are named.
- `DR-9` range/fallback is recorded; no setup or provider path is reachable.
- A reviewer can reproduce pure composition without history.

## Definition of Done

- Versioned immutable composition preserves floors and validates all stated ranges.
- Pure recovery/replay and every rejection are evidenced; no execution or authority is minted.
- `CF-POLICY`/`CF-SETUP-FRESHNESS`, deterministic/negative tests, exact evidence, diff/checks/CI,
  and independent review pass.

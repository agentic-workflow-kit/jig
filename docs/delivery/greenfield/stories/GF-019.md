# GF-019 — Work Source semantic contract

## Outcome, value, and why now

Define the exact Work Source exchange and plan validator with one scripted hostile fixture. This
releases validated candidate input to composition, enables GF-020 and GF-021, and leaves every real
source, approval, intake, Run, and dispatch impossible.

## Governing paths and stable IDs

`envelope-production.md` assigns source validation to `EP-SOURCE`; `runtime.md` keeps the Builder
outside core authority. `PORT-SOURCE` carries `ID-SOURCE-REQ` and returns
`SCH-SOURCE-EXCHANGE`; `SCH-PLAN` is design-owned input. `FC-INPUT`, `BND-RETRY`,
`BND-WAIT-MECHANISM`, and `operation_or_source_retry` define fail-closed bounded exchange;
`CF-ENVELOPE` and `CF-MECH-SOURCE` prove it. `DR-4` and `DR-12` permit only realization below that
contract. `PC-README-2`, `PC-README-3`, `PC-JIG-1`, `PC-JIG-2`, `PC-JIG-3`, `PC-JIG-7`,
`PC-JIG-19`, `PC-JIG-22`, `PC-JIG-23`, `PC-JIG-24`, `PC-CONCEPTS-1`, and `PC-CONCEPTS-9` map this
source boundary to the product's envelope, configuration, and one-track routes. `CFG-1`, `CFG-2`,
`CFG-3`, `CFG-4`, `CFG-5`, `CFG-6`, `CFG-7`, `CFG-8`, `CFG-9`, and `CFG-10` map respectively to
governance, profile, track floors, computed actual, guided setup, presets, open seams, prompt
guidance, freshness declaration, and owner posture; source input may satisfy none by itself.

## Dependencies plus start evidence

GF-002 must be merged with canonical identity/schema evidence and GF-004 with exact fixture and
suite-recorder evidence in the externally recorded execution base/tuple. The two edges are respectively `implementation`
and `evidence`; no branch, assertion, or provider result satisfies them. Reconfirm the Builder and
`PORT-SOURCE` boundary and the current `DR-4`/`DR-12` constraints before work.

## In-scope and non-goals

Scope is request/result validation, canonical source identity, plan graph/criteria/track/demand
validation, bounded exchange, and one scripted fixture. Structured files, any other format,
provider manifest/proof, policy/setup, approvals, intake, and all effects are excluded.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The Envelope Builder invokes `PORT-SOURCE`; the fixture returns candidate facts only. The Builder
validates request, cursor/revision, digest, provenance, and plan then emits an unapproved
composition input and diagnostic. Neither source nor fixture can approve, transition, dispatch,
publish, decide, review, finalize, create a Run, or write authority; test-only registration keeps
all concrete adapters unreachable.

## Observable success and terminal outcomes

Success is one exact request-bound exchange with an acyclic, one-track plan and valid criteria,
dependencies, demand, and reserves. Invalid, stale, ambiguous, changed, malformed, or exhausted
exchange facts are typed exchange failure/unavailable, not a Story outcome and not an intake
acknowledgement. No lifecycle state, Run, ledger, approval, or effect can result.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

`FC-INPUT` covers invalid bytes/binding. The immutable request records its `BND-WAIT-MECHANISM`
deadline and `BND-RETRY` ordinal; timeout/exhaustion leaves the source unavailable. A lost result is
re-read by the same request identity; changed content is a new candidate, never a blind retry.
Recovery reconstructs the request/bound facts; this scripted exchange has no effect, credential,
allocation, cleanup, or active-session resume.

## Security and trust: validation, credentials, redaction, and authority widening

Limit bytes, depth, graph work, strings, and duplicate keys; reject unknown versions, noncanonical
encodings, cross-track references, and unverifiable provenance. No credential is accepted. Redact
fixture diagnostics and retain only evidence digests. Candidate output, configuration, or fallback
cannot grant authority; construction guards prohibit an unqualified adapter from configuration or
effect dispatch.

## Deliverables without delegated algorithm invention

Deliver contract/schema/validator, scripted fixture, hostile corpus, and exact evidence records.
`DR-4` owner **Engineering + configuration** selects only a semantic-port transport, constrained by
the fixed exchange and `CF-MECH-SOURCE`; fallback is unavailable. `DR-12` owner **Engineering +
configuration** selects only a channel realization after its suite; fallback is source unavailable.
Any proposed realization or configuration selection requires an explicit current owner or
named-delegate implementation request covering GF-019; Arye separately owns any widening. No
parser, policy, or authority is delegated.

## Test and evidence obligations

Run canonical/schema, cycle/dangling/criteria/track/demand, hostile-limit, replay/permutation,
timeout/lost-result/recovery, and negative-authority tests. Record request/result/corpus/build/suite/
probe/bound/candidate digests for `CF-ENVELOPE`, `CF-MECH-SOURCE`, and the hostile source corpus.
Real-provider and E2E effect proof is inapplicable because the fixture is the only reachable adapter.

## Exact acceptance

An independent reviewer receives exact candidate and target basis, fixture/corpus and evidence
digests, suite/probe/build metadata, findings, and delivery metadata. Only an exact deterministic
review package with no unresolved finding may be accepted; merge/CI landing proof remains separate.

## DR choices

`DR-4`: semantic port transport, owner **Engineering + configuration**, fixed authority/evidence,
unavailable fallback, no new owner decision inside bounds. `DR-12`: scripted channel only, owner
**Engineering + configuration**, fixed validation, hostile-suite evidence, unavailable fallback;
concrete JSON needs GF-020. Widening or plan selection requires Arye.

## PR boundary, relative size, and split

`M`: one deterministic source/plan oracle, including fixture and corpus. It does not span a real
provider; GF-020 is the required semantic-to-provider successor, so no split is justified here.

## Definition of Ready

- GF-002 and GF-004 exact merged evidence and the externally recorded execution tuple are current.
- Ports, IDs, bounds, failure, authority fence, routes/imports, and oracles above are reviewable.
- `DR-4`/`DR-12` are bounded and only the scripted fixture is reachable.

## Definition of Done

- Canonical validation and bounded recovery fail closed without runtime authority.
- Required contract, hostile, replay, timeout, and negative-authority evidence passes.
- Exact review, required checks/CI, and `git diff --check` pass; no real source is configurable.

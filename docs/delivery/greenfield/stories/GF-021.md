# GF-021 — Envelope policy, profiles, setup, and bounds

## Outcome, value, and why now

Produce immutable validated policy/configuration composition, profiles, setup declarations,
guidance, and all bounded ranges. It releases a reviewable proposal basis for GF-022/GF-023 but
does not execute setup, read configuration, prove a provider, approve, create a Run, or dispatch.

## Governing paths and stable IDs

`EP-FLOORS` preserves floors; `EP-PROFILE` validates `SCH-WORK-PROFILE`; `EP-SETUP` declares the
future `SCH-SETUP-RECEIPT`; `EP-GUIDANCE` explains without authority; `EP-COMPOSE` emits the frozen
basis. `SCH-CONFIG-ARTIFACT`, `SCH-RULE-SURFACE`, and `configuration_read` bind exact inputs;
`FC-INPUT` fails closed; `DR-9` only tunes ranges; `CF-POLICY`, `CF-ENVELOPE`, and
`CF-SETUP-FRESHNESS` prove it. `PC-README-3`, `PC-JIG-1`, `PC-JIG-2`, `PC-JIG-3`, `PC-JIG-7`,
`PC-JIG-10`, `PC-JIG-12`, `PC-JIG-19`, `PC-JIG-22`, `PC-JIG-23`, `PC-CONCEPTS-1`,
`PC-CONCEPTS-9`, and `PC-USE-3` map envelope, safety, provider-posture, and composition routes.
`CFG-1`, `CFG-2`, `CFG-3`, `CFG-4`, `CFG-5`, `CFG-6`, `CFG-7`, `CFG-8`, `CFG-9`, and `CFG-10`
map the same governance/profile/track/computation/guidance/preset/open-seam/prompt/freshness/posture
commitments; the resulting data cannot choose a provider or widen authority.

## Dependencies plus start evidence

GF-002 implementation establishes canonical values, GF-004 evidence records exact proof, and
GF-019 implementation supplies valid plan input. All three must be merged in the externally recorded execution base/tuple;
current ranges, floors, and one-track boundary must be re-read. A preset, later receipt, or config
assertion is not evidence.

## In-scope and non-goals

Scope is pure floor proof, profile/artifact/setup declarations, policy/rule-surface validation,
composition digest, feasibility, bound catalogue, and guidance. Setup execution, artifact reads,
receipt production, provider/infrastructure qualification, preview/approval/intake, and Run
behavior are excluded.

## Runtime/product unit, ports, inputs, outputs, identities, persisted facts, authority

The external Builder validates owner/track inputs and produces a canonical unapproved proposal and
diagnostic projection. Owner/track author supplies intent; Builder may compose/explain only.
`SCH-SETUP-RECEIPT` is a future effect fact and no durable writer exists here. No actor may use
profile, guidance, or a declared setup to transition, approve, dispatch, publish, decide, or create
a Run; immutable input validation is the fence.

## Observable success and terminal outcomes

Success is a deterministic one-track composition preserving every floor, binding profile/artifact/
setup/rule-surface, capacity/reserve feasibility, and values inside declared ranges. Unknown,
weakened, incompatible, or out-of-range input is typed configuration failure/unavailable, not a
Story outcome. No receipt, provider proof, approval, acknowledgement, Run, or effect occurs.

## Failure, uncertainty, timeout, retry, reconciliation, recovery, cleanup, and resume

`FC-INPUT` covers unknown/noncanonical/out-of-range values. This story performs no exchange or
effect, so no timeout or retry is consumed. The future `configuration_read` is declared and must
later use its recorded bound chain; pure recovery recomputes immutable composition and mismatch
requires a new proposal. Nothing is allocated or cleaned up.

## Security and trust: validation, credentials, redaction, and authority widening

Reject hidden defaults, unknown rules, duplicate maps, oversized artifacts, weakened floors,
cross-track/profile references, and values outside ranges. Resolve no credentials; redact prompt/
guidance diagnostics to exact artifact digests. Policy/profile/guidance/setup data cannot become a
provider permission, setup effect, or runtime authority; no adapter is constructed here.

## Deliverables without delegated algorithm invention

Deliver immutable schemas, pure floor/composition/range validators, profile/setup/guidance
validation, fixtures, and evidence. `DR-9` owner **Configuration/policy** selects a value only in
the design-owned range; boundary proof is required and invalid input is unavailable. Any proposed
configuration selection requires exact external owner ratification/activation; Arye owns any
range/floor widening.

## Test and evidence obligations

Run canonical/determinism, floor-tightening, unknown-rule, profile/artifact/setup/rule-surface,
all range boundary, capacity/reserve, guidance-not-authority, and replay/no-Run tests. Record exact
policy/profile/artifact/setup/range/candidate/suite/probe digests for the three named suites.
Provider, crash, and effect E2E proof is inapplicable to pure composition.

## Exact acceptance

Independent review receives exact candidate/execution-base tuple, all configuration catalogue and vector
digests, evidence/delivery metadata, and resolved findings. Acceptance is exact-candidate review,
not owner proposal approval or landing; merge/CI proof is separate.

## DR choices

`DR-9`: question is numerical tuning; owner **Configuration/policy**; bounded selected values;
immutable ranges/exhaustion; boundary evidence; invalid input fallback; any new range/floor requires
Arye. No other choice is opened.

## PR boundary, relative size, and split

`L`: one pure composition oracle. Split only `GF-021a` validator/core from `GF-021b` guidance if
the first remains green and both use identical schemas; setup execution/configuration I/O remains
excluded.

## Definition of Ready

- The three exact dependencies and governing catalogue are merged/current.
- All mapped IDs/routes/imports, authority fence, future facts, failure, and proofs are named.
- `DR-9` is bounded and no provider/setup effect is reachable.

## Definition of Done

- Immutable composition preserves floors and validates every declared range.
- Deterministic/negative/boundary evidence and exact review/checks/CI pass.
- No pre-Run configuration result is rendered as a Story outcome or runtime authority.

# Greenfield story index

Read the [story contract](../story-contract.md) before any brief. Then read the phase in order,
verify its declared dependencies and current exact evidence, and treat the linked product/design
paths as controlling. A story is a planning contract, not permission to create product source,
choose a new `DR-*`, or reuse archived implementation as architecture.

For cold review, begin with the [greenfield overview](../README.md),
[track manifest](../track.json), [delivery policy](../delivery-policy.md), and
[reviewer packet](../reviewer/README.md). Use the manifest rather than this index for exact
dependencies, inventories, provider gates, and counts.
